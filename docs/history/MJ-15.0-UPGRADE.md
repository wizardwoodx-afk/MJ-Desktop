# MJ 15.0.0 — UPGRADE: what is proven and what is not (the Vouch Harbor face)

*The Teammate door: the human face of the Mission Loop. Six doors, the app
opens on the face.*

## What changed

1. **The Teammate door** — a named, persistent seat (default persona: ROGUE)
   you message like a colleague. It is a door onto the SAME engine, not a
   second product: it drives real tools, pauses at the human gate for risky
   actions, can dispatch objectives into the real Mission Loop, and mints a
   signed receipt for every finished run.
2. **`src/mission/teammate.ts`** — the teammate engine module; the page's
   only import (the 12.0 engine rule, extended and probe-pinned by
   `probe/teammate.test.ts`).
3. **`receipts.buildChainedReceipt`** — the generic event-list minter on the
   shared mj-proof-receipt/2 protocol. The Mission Loop path
   (`buildProofReceipt`) is untouched and probe-pinned as before.
4. **IA** — PageKind, nav map, App route, page and probes moved together:
   six doors; the engine group is teammate + loop + workflow; the app opens
   on the Teammate door.
5. Version bumped to 15.0.0 across all manifests (the versionDrift gate
   enforces this); offline verification pack rebuilt with the new suite.

## What is proven (the gates, re-run against this tree)

- `tsc --noEmit` — zero type errors.
- `npm test` — 82 live suites, including the new `teammate` probe: the engine
  rule (page imports only the module), the human gate (a run PAUSES until the
  approval resolves; approve → the write lands in the local workspace and the
  receipt records `approved: true`; deny → nothing executes and the receipt
  records `approved: false, ok: false`), tamper detection (a forged event
  breaks verification), the receipt round-trip (mint → verify offline →
  JSONL), the labeled brain, and the real calculator (no eval).
- The offline verification pack is rebuilt byte-pinned; `node verify/run.mjs`
  re-runs the whole pack with zero MJ state.

## What is NOT (yet) — the honest gaps

- **The brain is simulated.** 15.0's teammate decisions are offline,
  rule-based, and labeled as such in the UI and in every receipt
  (`brain: simulated`). The `TeammateBrain` seam exists for 15.1: a
  model-backed brain (provider configured in the System door) plugs in with
  zero page changes. No claim is made that the simulated brain is a model.
- **The workspace is a local file store, not the OS file system.** 15.0's
  `workspace_write` writes to a namespaced store on this machine (visible in
  the rail, recorded in the receipt) and is clearly labeled. Real OS-level
  file/terminal tools behind the same human gate are the 15.1+ scope, and
  they will use the Tauri permission model, never a silent grant.
- **One seat.** 15.0 ships one persistent teammate. Multi-seat crews
  (multiple named teammates with separate memory and scopes, coordinating
  over the bus) is the 15.x roadmap — the receipt protocol and the bus
  already carry the shape.
- **Dispatch needs a composed crew.** `dispatch_mission` drives the real
  `runMissionLoopCycle`; with no crew composed it refuses honestly. It does
  not invent a crew.
