# MJ 11.11 — SELF-EVOLVING upgrade notes

The AGI-grade autonomy release. "AGI-grade" is used the only way it can be used
honestly in 2026: not a claim of general intelligence, but the closed loop the
research literature converges on — execute, evaluate, reflect, remember, improve —
implemented over MJ's measured runtime, with proof attached to everything learned.

## 1. Lessons memory (`src/mission/lessons.ts`)

After every team run, `reflectOnMission` derives plain-language lessons from facts
the run already produced: failure classifications, the repair ladder that recovered
it, seat outcomes, the gate verdict. Lessons carry their evidence, decay
(`DECAY_PER_DAY = 0.95`), reinforce on repetition instead of duplicating, and are
retrieved by strength × recency × goal overlap. `teamExecutor` injects the retrieved
lessons into every seat's briefing as `.mj-brief/ORG_LESSONS.md`, budgeted by the
adopted strategy's `lessonBudget`.

Honesty rule: a simulated run produces exactly one environment lesson — nothing
about real execution may be learned from a run that did not execute.

## 2. Strategy self-improvement loop (`src/mission/selfImprove.ts`)

An archive of team strategy versions in the Karpathy/HyperAgents pattern, reduced
to fleet orchestration: one mutated candidate per generation (dimensions rotate:
review depth, check bias, serial exec, lesson budget), evaluated on measured runs
only. `scoreRuns` returns null when every run was simulated, and a null score never
settles — the candidate waits with a written note. Adoption requires a strict
`ADOPT_MARGIN = 0.05` over the adopted parent's measured score; losers retire with
the numbers that condemned them.

## 3. Skill evolution (`src/mission/skillEvolution.ts`)

Self-evolving agents grow their own toolsets; MJ does it with a human in the loop.
Proposals come only from verified, non-simulated missions (a role that passed two
or more tasks) or from a failure lesson that recurred three times. Proposals never
install themselves: the Evolve page shows Approve/Discard, and an approved skill
rides in future briefings and appears under "Learned skills" in the library drawer.

## 4. Learning receipts (`src/mission/learningReceipt.ts`)

What the organization learned is signed. A learning receipt freezes the lesson set
and any strategy-version change, digests it with SHA-256 over key-sorted,
lesson-order-stable JSON, and carries the issuer's Ed25519 signature when the
runtime supports it — otherwise a written `signatureNote`, never a silent fake.
`verifyLearningReceipt` recomputes from zero MJ state.

## 5. Wiring

- `teamExecutor.executeTeam` injects org lessons into worktree briefings.
- `pages/TeamsPage.tsx` settles the loop on the same measured report the autonomy
  engines and the proof receipt consume (`settleSelfEvolution`).
- `pages/EvolutionPage.tsx` shows the memory, the strategy archive, pending skill
  proposals (approve/discard) and learning receipts (verify button).
- `panels/LibraryDrawer.tsx` lists approved learned skills.

## 6. Verification

New probe suite `probe/selfEvolve.test.ts` pins: reflection determinism and the
simulated-teaches-nothing rule; decay/reinforcement/cap/retrieval; measured-only
adoption with the strict margin; proposal honesty; receipt verification and tamper
detection; canonicalization stability.
