# MJ 12.0.2 — Feedback integrity (architecture freeze point)

*Release pointer. Full notes live in the CHANGELOG row (12.0.2); this file
names what changed and where.*

## Why 12.0.2 exists

The 12.0.1 review scored the architecture 9.8/10 and named exactly two things
to fix before freezing. Both are closed:

1. **Team binding in `submitHumanFeedback()`** (`src/mission/missionLoop.ts`).
   The API checked the cycle existed but not that `args.teamId` equals the
   team that ran it. A rating for Team A's cycle filed under Team B's id
   would have written into Team B's seat records. Now refused before any
   store write: `cycle <id> ran team <X>, not <Y>`. Probe proves the
   evolution store stays byte-identical and the loop state untouched.

2. **Per-run supersede in the feedback queue** (`src/mission/teamEvolution.ts`
   `applyTeamFeedback`). Queued entries now carry `runId`; appending a new
   rating for a run drops any unconsumed entry for that same run first. The
   UI's "one current rating per cycle" is now true of the pipeline too:
   4/5 → 2/5 → 5/5 before the next fold queues exactly the 5/5, and the
   superseded 2/5 comment provably never reaches the evidence (no pretend
   criticism from a rating the human changed). The verbatim `store.feedback`
   history still records every submission, one row per seat.

## Architecture freeze

The 12.0 shape is now locked: one canonical orchestrator (missionLoop) over
the engines of record, one loop ledger, one product API, five doors, explicit
human feedback bound and supersede-safe inside the loop. The next meaningful
step is not another consolidation patch — it is proving the single Mission
Loop changes real agent-team behavior over repeated runs with real users.
