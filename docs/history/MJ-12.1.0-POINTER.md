# MJ 12.1.0 — Knowledge Forge (books → human-approved skills)

*Release pointer. Full notes live in the CHANGELOG row (12.1.0); this file
names what changed and where.*

## The capability

The OSS book-to-skill movement proved good documents distill better than they
dump; MJ now has the capability natively, under its own honesty rules.
`src/mission/knowledgeSkills.ts` distills a document into a structured
knowledge proposal: a deterministic mechanical extractor (frameworks,
decision rules, code patterns — structure, not summaries), optionally
enhanced by an LLM pass that runs through MJ's OWN installed harness CLIs
(local, no API keys, no uploads).

## The six guardlines (each probe-pinned, 34/34)

1. Provenance mandatory: real SHA-256, byte length, tool+version, distiller,
   time.
2. No structure → no proposal: unstructured blobs refused in words.
3. Nothing installs silently: proposals start proposed; one recorded human
   decision each; a second decision is refused.
4. Knowledge ≠ learning: `claimsMeasuredEffect: false`, lessons/autonomy/
   bandit untouched, briefings label it `[knowledge]`.
5. LLM pass is best-effort with an honest fallback: missing binary, garbage
   output or crash → mechanical, reason written into the proposal, never
   credited to a model.
6. Approval mirrors into skill memory (`mj.skills.v1`) as an approved
   `[knowledge]` RECOURSE via the governed human write, and then rides every
   future mission briefing through the same `approvedSkillDefs` path
   verified-mission skills use.

## Product surface
