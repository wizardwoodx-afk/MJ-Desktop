## 14.1.1 — the trust-anchor fix + mission-complete economics

**The trust model, corrected (the reviewer's forgery attack, closed).** A signed
artifact carries its own issuer public key — and signature math alone can never prove
that key belongs to MJ. Both standalone verifiers now treat the issuer key as what it
is: a claim that must be PINNED out-of-band.

- `--issuer-key <hex64 | @file>` pins the trusted Ed25519 key: match → `issuer
  AUTHENTICATED` (exit 0, SHA-256 key fingerprint printed); mismatch → `INVALID` (exit 1).
- No pinned key → `VALID SIGNATURE — issuer UNVERIFIED` (exit 3, fingerprint printed,
  never presented as authenticated). Unsigned records → `VALID DIGEST … no issuer
  authenticity is claimed` (exit 3).
- Language corrected everywhere: **zero MJ state required, issuer key pinned
  out-of-band** — never "zero trust required".

**Mission-complete economics.** The Mission Record's `economics` no longer shows only
the last cycle: `perCycle` carries a chargeback row per cycle (the exact CSV
derivation) and `totals` carries the mission view — measured spend, unmeasured and
over-budget cycles, overrun, tokens-only/simulated seats, and the shared-cap
`missionBudgetUsd` / `missionAdherence`.

Gates re-certified under the standalone node v22.23.2 (tsc 0 · 81/81 live · 80/80

## 1 · The Mission Record — `mission/missionRecord.ts`

The unifying artifact: **one Ed25519-signed, hash-digested file per mission** carrying

- **authority & execution** — cycle records: seats, outcomes, gate tiers, arena digests;
- **economics** — the chargeback row (byte-identical derivation to the FinOps CSV, so
  the record and the export can never disagree);
- **risk context** — the fleet assurance figure, *labeled* `scope: "fleet"` (a mission
  record never claims a per-run safety grade);
- **evidence** — every vault receipt, re-verified at seal time and again at verify
  time; broken receipts are carried WITH their mark, so the record cannot look
  healthier than its evidence;
- **the timeline** — the canonical incident chronology.

Four readers, one file: finance reads `economics`, audit reads the chained receipts,
risk reads `assuranceContext`, incident response reads `timeline`. Anyone verifies
with zero MJ state:

```bash
node tools/verify-mission-record.mjs record.json   # VALID / INVALID + reason
```

Honesty rules (probe-pinned by `probe/missionRecord.test.ts`): assembled only from the
stores the Mission Loop wrote; unsigned records must carry a signatureNote; flipping an
economics number, a signature, or an evidence mark fails verification.

**The story this completes:** one mission, one record, zero trust required.
