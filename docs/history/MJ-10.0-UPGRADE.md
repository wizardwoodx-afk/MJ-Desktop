# MJ 10.0 — what changed, and exactly what is proven

V10 completes the work V9 started: the orchestration layer that V9 fixed is now visible in the app, and
the two remaining V9 modules (`replay`, `evals`) exist, are wired into a page, and are tested.

## 1. Version metadata: one source of truth

`src/version.ts` holds `MJ_VERSION` and everything else reads it. Aligned to **10.0.0**:

| File | Value |
| --- | --- |
| `package.json` | 10.0.0 |
| `package-lock.json` (top level **and** `packages[""]`) | 10.0.0 |
| `src-tauri/Cargo.toml` | 10.0.0 |
| `src-tauri/tauri.conf.json` | 10.0.0 |
| `src/version.ts` | 10.0.0 |
| README / DESKTOP-NATIVE / INSTALL-ON-LAPTOP / LOCAL-WORKLIST titles | MJ 10.0 |

`SettingsPage.tsx` and `ipc/client.ts` import `MJ_VERSION` instead of hardcoding a release number —
which is *why* the version drifted to 4.0.0 / 6.0.0 / 7.0.0 in the same tree in the first place.
`probe/versionDrift.test.ts` fails on any disagreement; it was checked for vacuity by bumping only
`src/version.ts`, which produced 10 failures and exit 1.

The project folder is `mj/` with no version suffix.

## 2. New in V10

### `src/mission/replay.ts` — reconstructable state, not a transcript

`FlightRecorder.replay(seq)` already returned events up to a sequence number. That is a log, not a
state, so it cannot answer *"what was true then?"*. `replay.ts` folds those events into a
`MissionProjection`: agents and their harnesses, artifacts and evaluations, spend, tokens, approvals,
repairs, failures, limits, rollbacks — plus the ordered list of decisions with their authority and
evidence.

On top of that: `diffProjections` for field-level change between two moments, `decisionAt` for the state
either side of a choice, and `timelineTicks` for a scrubber.

**Honesty rule:** `counterfactualHarness` never produces a result. It returns
`"unknown — this was not re-run"` plus what a real test would require. Scoring an alternative harness
that was never run would be fiction, and a decision made on that number would be worse than no number.

### `src/mission/evals.ts` — which CLI is good at *this project's* work

A named suite of real tasks with real checks, run against real harnesses. Three rules:

1. **An errored case is never counted as a pass.** It stays in the denominator and sets `hasErrors`.
   Excluding errors is how a suite that could not run at all displays 100%.
2. **Cost is unknown when the harness reports none.** Several CLIs report tokens but no price; summing
   those as $0.00 and comparing them to a harness that does report price ranks on an artefact.
3. **A comparison only compares runs of the same suite**, and a run with errors can never be the leader.

`readHistoryRow` returns `hasErrors: true` for a row whose details cannot be parsed — the safe reading.

### `src-tauri/src/git.rs` + `git_core.rs` — the repository as git sees it

Six commands: `git_is_repo`, `git_status`, `git_diff`, `git_head`, `git_branch`, `git_read_only_check`.

The parsing lives in `git_core.rs`, which is plain `std` and is `include!`d verbatim into `git.rs`. That
split is load-bearing: `cargo check` cannot run on the full Tauri crate anywhere but a developer's
machine, so parsers kept inside `git.rs` could never be compiled or tested before shipping. As it stands
the *shipped file itself* is compiled against a minimal `tauri` stub and its 18 tests run here.

Three details worth naming:

- `git status --porcelain -z` is parsed as NUL-separated because that is the only form where a filename
  containing a newline survives, and the only one where a rename's two path fields are unambiguous.
- **A rename's first path field is the destination, the second is the origin.** Verified against real
  git (`git mv old.txt new.txt` → `R  new.txt\0old.txt\0`), not inferred. Getting it the other way round
  reports the deleted path as the live one.
- A timeout is returned in the value with `ok: false` and the partial output, not as `Err`. `Err` for
  both "could not spawn" and "deadline reached" makes those indistinguishable and throws away whatever
  git printed before it was killed.

`git_read_only_check` answers three ways: `clean`, `violated` (with the paths), or `unknown`. An
unreadable status is **never** reported as clean — that is precisely how a write goes unnoticed.

### `src/pages/V10Page.tsx` — the Proof page

Registered as `PageKind "proof"` with a nav entry. It is not a dashboard; every panel is one of:

1. a pure computation over real definitions (capabilities, composed argv, merge ordering, caps),
2. a real call (git through IPC, evaluation history through SQLite, replay over a live flight recorder),
3. a statement that the thing is unavailable here, with the reason.

There is no fourth category. The git panel in a browser build says git is unreachable rather than
rendering "0 files changed".

### `src/ipc/client.ts`

`useTauri` is exported so pages can *label* what they are showing, and the six git methods throw in a
browser build instead of returning empty results — with result types mirroring `git.rs`.

## 3. The reviewer-visibility fix (carried from V9, proven by execution)

Read-only seats were handed `repoRoot` while writers committed to private branches, so reviewers
reviewed the **pre-work tree**. Writers now get worktree+branch `mj/<slug>/<seat>`; between waves MJ
builds `mj/<slug>/review` = base + every committed writer branch (`--no-ff`, `checkout -B` so re-runs
reset) and gives each read-only seat a detached worktree on it. The snapshot SHA is recorded on every
`SeatRecord.reviewedSha`.

Real run: coder fixed `sub()` on `mj/fix-sub/coder`; reviewer ran detached on snapshot
`442a4fdd…` and answered **"CORRECT"**; the base checkout stayed on `master` at `initial commit`, still
carrying the bug.

Two further defects found only by running it: MJ left the user's checkout on the snapshot branch, and
briefings were committed into the agent's code because git does not read `info/exclude` from a linked
worktree's own git dir — only the common one. Both fixed; the exclusion is now verified with
`status --porcelain` before MJ claims it held.

## 5. What is NOT proven — stated plainly

- **`cargo check` has never run on the full Tauri crate.** `git.rs` was compiled against a minimal
  `tauri` stub with a no-op `#[tauri::command]`; the real macro and the real `tauri::generate_handler!`
  registration in `lib.rs` have not been compiled. webkit2gtk-4.1, gtk+-3.0 and libsoup-3.0 are absent
  from this container and there is no root to install them.
- **No installer has ever been produced.** `INSTALL-ON-LAPTOP.md` is a worklist, not a build log.
- **Only Claude Code 2.1.197 and OpenCode 1.18.25 are verified against real binaries.** The other seven
  harness surfaces carry per-claim confidence levels and are listed as unverified in the Proof page.
- **The Proof page has not been opened in a real WebView.** `probe/v10Page.test.tsx` renders it to a
  string with `react-dom/server` and asserts on the output — browser mode, a faked Tauri host, and the
  error path all render without throwing, and no panel shows a number it did not obtain. That covers
  crashes and fabricated defaults, not CSS, layout, or anything that needs a real DOM.
- **`useEffect` does not run under `renderToStaticMarkup`**, so the evals panel is asserted in its
  pre-data state. Its loaded and error states are exercised by `probe/replayEvals.test.ts`, not here.

## 6. Reproduce

```bash
cd mj && npm ci
./node_modules/.bin/tsc --noEmit
for f in versionDrift acceptance harnessPolicy checkRunner realExecution engine replayEvals reviewVisibility; do
  ./node_modules/.bin/esbuild probe/$f.test.ts --bundle --platform=node --format=esm \
    --define:MJ_ROOT='"'$(pwd)'"' --outfile=/tmp/$f.mjs --log-level=error && node /tmp/$f.mjs
done
./node_modules/.bin/vite build

# reviewVisibility needs a real CLI on disk:
npm i --prefix /tmp/oc opencode-linux-x64      # opencode-ai fails on glibc here
export MJ_OPENCODE_BIN=/tmp/oc/node_modules/opencode-linux-x64/bin/opencode

# Rust: the parsers, standalone
export PATH="$HOME/.rustup/toolchains/stable-x86_64-unknown-linux-gnu/bin:$PATH"
```

`--define:MJ_ROOT` is required for `versionDrift`: `import.meta.dirname` is undefined in an esbuild
bundle, so without it the probe resolves the project root to `/` and crashes on `/package.json`.
