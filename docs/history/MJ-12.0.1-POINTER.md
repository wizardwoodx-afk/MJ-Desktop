# MJ 12.0.1 — The Human-Feedback-in-the-Loop patch

*Release pointer. Full notes live in the CHANGELOG row (12.0.1) and in the
code the row describes; this file names what changed and where.*

## Why 12.0.1 exists

The 12.0.0 review confirmed the ONE-ENGINE fusion (orchestration-layer merge,
not UI) and raised three open items. 12.0.1 closes all three:

1. **The explicit human feedback regression (the most important finding).**
   Pre-12.0, TeamsPage carried the 1–5 rating + comment interaction feeding
   `applyTeamFeedback()` → queued evolution evidence. 12.0.0 retired the page
   without migrating the interaction, so the engine's feedback was measured
   outcomes + accept/reject only. 12.0.1 restores it INSIDE the Loop:
   - Engine API: `missionLoop.submitHumanFeedback({cycleId, teamId, rating,
     comment})` — validates, attaches the rating to every seat that ran the
     cycle through the same `applyTeamFeedback` pipeline the old page used,
     and records one current entry per cycle in the loop state
     (`feedbackByCycle`).
   - Fold semantics (pre-existing in teamEvolution, now reachable again):
     1–2 becomes weight-2 `Human: <comment>` evidence at the next ADAPT;
     4–5 arms praise suppression; 3 is neutral; queues are consumed exactly
     once.
   - Surface: the Loop page renders a rating panel (1–5 + comment) on every
     cycle in the ledger. Probe-pinned in `probe/missionLoop.test.ts` §5
     (12 new assertions, suite 56 → 67/67).

2. **The page-to-engine boundary tightened.** LoopPage now imports only the
   engine module. Crew persistence (loadCrews/persistCrew), the host-deps
   adapter (loopHostDeps) and the bus projection (loopBusFeed) moved behind
   missionLoop's API. navAlign's forbidden list grew to include
   agentTeam/hostDeps/interAgentChannel (32 → 39/39).

3. **The claims corrected.** "ONE engine, ONE cycle, ONE store" overstated
   the fusion. missionLoop is ONE canonical orchestrator over MJ's engines of
   record (team evolution, autonomy/bandit, lessons, receipts, bus, crew
   persistence); it does not fuse them into one physical store. The module
   header, IA doc and changelog state the precise model; navAlign pins the
   honest wording (no "one store" overclaim may return).
