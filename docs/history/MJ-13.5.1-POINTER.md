# MJ 13.5.1 — patch notes (the skill/implementation agreement fix)

*Release pointer. Full notes live in the CHANGELOG row (13.5.1); this file
names what changed and where. The 13.5.0 review (9.85/10) found exactly one
technical issue; this patch closes it, then the design system is FROZEN.*

## 1. The reviewer's finding

`skills/ui-motion-language/SKILL.md` said "Animate only `transform` and
`opacity`", while the NATURA CSS (13.5.0) also transitions paint properties
— box-shadow, border-color, background, color, stroke. The shipped skill was
**stricter than the implementation it documents**. Since 13.5's proposition
is that the skills are the rules by which MJ is designed, the rules must
match reality. The reviewer offered two fixes and recommended the first.

## 2. The fix (reviewer's option 1)

The rule now reads:

> **Layout motion uses only `transform` and `opacity`** — never width,
> height, top, left, margin; layout animation is jank, and transform keeps
> the GPU path. **Visual-state transitions may also animate paint
> properties** — box-shadow, border-color, background, color, stroke and
> fill — because they do not trigger layout; keep them short (≤ 200ms) and
> use them for state, not entrance.

No CSS changed: the implementation was already the correct, nuanced one; the
documentation now says what the code does.

## 3. Pinned so it stays true

`probe/meridian.test.ts` gains a 46th assertion: the motion skill must keep
the nuanced rule (layout = transform/opacity; paint allowed for state) and
must never regress to the stricter absolute. **46/46.**

## 4. Design freeze (per the review)

With the skill aligned, the design system is now FROZEN at the INK six +
NATURA material/motion + the three design skills. Future UI work extends the
frozen system through the skills; it does not invent new palettes or motion
languages. The highest-value next work is real users, real repeated
missions, real human feedback and real evidence — not another internal
release.
