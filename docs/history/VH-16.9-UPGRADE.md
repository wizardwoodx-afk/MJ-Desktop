# VH 16.9.0 — the modern-client release (official MCP SDK v2 conformance)

*Vouch Harbor 16.9.0 — the accountable agent OS (govern · execute · verify · learn).*

The 16.7.0 external review (9.85/10) named the biggest remaining MCP gap:
the official client validation covered the **legacy** path
(2025-11-25, official v1 SDK, probe #90) but not the **modern** path
(2026-07-28). 16.9 closes it with the official client of the modern era:
**`@modelcontextprotocol/client` v2.0.0** — the stable v2 line of the
MCP TypeScript SDK, which implements the 2026-07-28 specification
(pinned devDependency, exact version, conformance tool only).

## What probe #92 (`mcpSdkClientV2`, 10 tests) proves

The v2 client drives the REAL server over real stdio with the era
**pinned to 2026-07-28** (pin mode: no probe-and-fallback — a server that
cannot serve the revision fails loudly):

1. **Pinned negotiation lands on 2026-07-28** — the official modern
   client and our stateless modern core agree on the revision; the
   end-to-end proof is behavioral (the MRTR flow below exists only on
   the modern wire).
2. **`server/discover` reaches the client** — both eras advertised
   (dual-era from the outside), capabilities + cache hints present.
3. **The 20-tool governed surface, deterministically ordered.**
4. **Safe calls return real output** in the modern result shape.
5. **The human gate, the MODERN way (MRTR)** — a gated call returns
   `resultType: "input_required"` with the decision embedded as an
   `elicitation/create` input request plus an opaque `requestState`;
   the SDK's multi-round-trip auto-fulfilment answers it through the
   registered elicitation handler and retries the call with
   `inputResponses` + the byte-exact `requestState` echo. Approve →
   executed → the receipt verifies `VALID` → the write is in the
   workspace store. Decline → reported in words, the workspace store
   is checked and the file is NOT there. The entire interactive
   round-trip happens inside `callTool()`.
6. **Honest refusals over the modern wire** — unknown tool and a drill
   on a missing harness refuse in words (`ok=false`), never a fake
   run.
7. **Dual-era from ONE official client library** — the same v2 SDK in
   its default (legacy) posture still negotiates 2025-11-25 via the
   classic initialize handshake and sees the same 20-tool surface.
   One client library, both eras, externally proven.
8. **DevDependency hygiene** — the v2 client is a conformance tool,
   never product runtime (probe-pinned, as the v1 client is).

Together with probe #90, the external-client picture is now complete:
**legacy era proven by the official v1 client, modern era proven by the
official v2 client** — both driving the same governed server.

## What did NOT change

- No new MCP tools, no wire change for any existing client (the
  dual-era router is untouched — this release validates it from the
  outside, it does not modify it).
- The 20-tool surface, the deterministic drill and its attestations,
  the genome engine (16.8) are untouched.
- One new devDependency: `@modelcontextprotocol/client@2.0.0` (exact
  pin; `>=20` engine — both certified runtimes).
- Counts: **91 live probe suites / 90 offline verification bundles**
  (+`mcpSdkClientV2`, 10 tests).
