# MJ 11.8.5 — the vendoring + CI-currency release

11.8.5 closes the gap between what MJ says it wraps and what it actually ships, and removes a
runtime regression that 11.8.1 introduced in its last commit.

## 1. The browser-compat fix, done at the right layer

`agentsMd`, `sandbox` and `teamExecutor` import `node:fs` / `node:os` / `node:path` because the
probe suites run them directly under Node — they must test the real builtins, never a double.

**11.8.1** tried to solve the browser half at runtime:

```ts
let fsSync: typeof import('fs');
try { fsSync = require('fs'); } catch { fsSync = {} as any; }
```

That fails twice over:

1. In an ESM bundle `require` is **not in scope**, so the `try` threw under Node too. The probes
   silently exercised an empty object, `agentsMd` lost five assertions and then hard-threw on
   `fsSync.mkdirSync is not a function`, and `npm test` fell to **38/40**.
2. `{}` degrades **quietly**. `collectAgentsContext` wraps its `statSync` in a catch whose comment
   reads *"no file here — that is the normal case"*, so a dead filesystem became indistinguishable
   from an empty workspace. MJ planned missions on missing ground truth and reported it as clean.

**11.8.5** keeps the static ESM import and moves the seam to the bundler, where it belongs:

- `src/browser/nodeStubs/path.ts` — `path` is pure string logic, so this is a **faithful
  implementation**, not a stub.
- `src/browser/nodeStubs/fs.ts`, `os.ts`, `fs-promises.ts` — a WebView has no filesystem and no
  temp directory, so every entry point **throws an error that names itself**. Degradation now
  surfaces as a stated cause ("AGENTS.md scan failed: …") instead of a silent zero.
- `vite.config.ts` aliases the three specifiers, **anchored** (`/^node:fs$/`, `/^node:fs\/promises$/`).
  A bare `"node:fs"` key is a prefix match and rewrote `checkRunner.ts`'s
  `await import("node:fs/promises")` into `…/fs.ts/promises`, failing the build with `ENOTDIR`.

The probe runner calls esbuild directly and never reads `vite.config.ts`, so Node keeps the genuine
builtins and the suites keep testing real code.

## 2. The vendored engines now exist

`VENDOR.md` documented five trees that were **not in the repository**. `hermes.rs` resolved the
bridge as `<vendor>/evolution-service/mj_evolution/stdio_server.py`, but there was no `vendor/`
directory at all and nothing created one — so `hermes_bridge`, `evolution_service_propose` and
`evolution_service_health` could not work in any fresh clone. No probe asserted on that path, which
is why the suite stayed green.

11.8.5 ships them:

| Directory | Upstream | Licence |
|---|---|---|
| `vendor/hermes-agent` | NousResearch/hermes-agent | MIT |
| `vendor/hermes-agent-self-evolution` | NousResearch/hermes-agent-self-evolution | MIT (declared) |
| `vendor/mcp-servers-reference` | modelcontextprotocol/servers | MIT / Apache-2.0 |
| `vendor/mcp-github` | github/github-mcp-server | MIT |
| `vendor/evolution-service` | **MJ (first-party)** | MJ proprietary |

- `vendor/hermes-agent` is **pruned** to what MJ consumes — `LICENSE`, `README.md`, `agent/`,
  `skills/` — taking it from 258 MB / 11,300 files to 12 MB. MJ does not wrap the upstream desktop
  app, website, tests or CLI extras, so it does not ship them.
- `evolution-service/` **moved** to `vendor/evolution-service/` — the path `hermes.rs` already
  resolves. This fixes the bridge with **zero Rust changes**, which matters because the Rust
  toolchain is not available in the environment that produced this release.
- `tauri.conf.json` gains `bundle.resources: ["../vendor"]` so the engines ship inside the installer.
- `NOTICE` records every upstream licence, and flags that `hermes-agent-self-evolution` declares MIT
  in `pyproject.toml` **without shipping a LICENSE file** — confirm that grant before commercial
  redistribution.

## 3. Verification

Run on a fresh `npm ci`, Linux x64, Node v20.20.2:

| Gate | 11.8.1 (as shipped) | 11.8.5 |
|---|---|---|
| `tsc --noEmit` | exit 0 | exit 0 |
| `vite build` | exit 0 | exit 0 |
| `npm test` | **38 / 40** | **40 / 40** |
| `node verify/run.mjs` | 39 / 39 — on **stale** bundles | **39 / 39** — on a fresh, byte-pinned pack |

The 11.8.1 offline number deserves the emphasis: it passed because `verify/suites/` had been built
from pre-regression source. The offline gate is only meaningful alongside suite #40, which is the
check that catches staleness — and #40 was the one failing.

## 4. CI runner currency

A workflow that cannot allocate a runner verifies nothing, and a CI badge nobody can reproduce is
decoration. Runner images retire on a published schedule, and nothing else in the suite would have
noticed: version strings would still agree, bundles would still be byte-identical and every probe
would still pass — on a pipeline GitHub refuses to start.

Status at the time of writing (2026-09-03):

| Label | Status | Action |
|---|---|---|
| `macos-13` | support ended **2025-12-04** | was in `release.yml` — removed |
| `macos-14` | deprecated; brownouts 2026-10-29..31, unsupported **2026-11-02** | moved to `macos-15` |
| `ubuntu-22.04` | active support ends **2026-09-17** | moved to `ubuntu-24.04` |
| `ubuntu-20.04`, `macos-12` | long retired | n/a |

- `ci.yml` → `ubuntu-24.04`, `macos-15`, `windows-latest`, **Node 22** (Node 20 reached EOL
  2026-04-30; CI should not certify a release on an unsupported runtime).
- `release.yml` → `ubuntu-24.04`, `macos-15` (arm64), `macos-15-intel` (x86_64), `windows-latest`,
  Node 22, with the Rust target expression updated to match the new labels.
- The release gate now runs **`npm test`** — the same 40 suites CI runs — instead of a hand-picked
  5-suite subset. Shipping installers certified by a subset certifies nothing about the other 35.
- `releaseBody` names `MJ-11.8-UPGRADE.md` instead of `MJ-11.0-UPGRADE.md`.
- `probe/versionDrift.test.ts` gains **§5**, which fails the gate if a retired runner label
  reappears in any workflow. It scans executable lines only, because a comment may legitimately
  *name* a retired label to explain why it is banned.

Both new checks have verified mutation tests (manual probe negation verification): re-pinning macOS x86_64 to `macos-13` → **21 passed, 1 failed**;
pointing `releaseBody` at the stale doc → **21 passed, 1 failed**. Revert → **22 passed, 0 failed**.
(Self-mutation pack check exists; external automated mutation framework is not integrated).

## 5. Not done here

- **Rust is unverified in this environment** (no cargo toolchain). `cargo check`, `cargo test` and
  `cargo clippy -D warnings` remain CI's report, not a claim this release makes. The vendoring fix
  was deliberately chosen so that no Rust source needed to change.
- The frontend build stack is 1–2 majors behind: React 18 → 19, Vite 6 → 8, TypeScript 5 → 7.
  Runtime dependencies (Tauri 2.11.5, `@tauri-apps/api` 2.11.1, zustand 5.0.15) are current.
