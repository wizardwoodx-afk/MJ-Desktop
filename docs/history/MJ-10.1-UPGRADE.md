# MJ 10.1 — UPGRADE

The change in one sentence: **MJ ships a fourth theme — `nothing`, the Nothing OS design language
(OLED black, #1B1B1D surfaces, signal red #D71921, bundled dot-matrix display type) — plus a
debugging pass that fixes ten defects the probes were not yet covering, and a new probe
(`theme`) that pins the theme system shut.**

## 1. The `nothing` theme

Nothing's design language, mapped onto MJ's token system (`[data-theme="nothing"]` in
`src/styles/mj.css`):

| Token / surface | Value | Why |
|---|---|---|
| `--bg` | `#000000` | OLED black canvas — the Nothing phone default |
| `--nk-surface-3` / hovers | `#1B1B1D` | the Nothing OS dark-gray surface |
| `--amber` (accent alias) | `#D71921` | signal red — an interrupt, not decoration |
| `--amber-hot` / `--danger` | `#FF2D36` | the red at its hottest |
| `--font-doto` | `"Doto"` | dot-matrix display type (NDot's open, OFL cousin), bundled as a 5 KB variable woff2 at `src/assets/fonts/doto-var.woff2` |
| `--r-sm/md/lg` | 0 / 1 / 2 px | sharp, technical geometry |
| `--t-fast/med` | 90 / 140 ms ease-out | percussive, not fluid |

What it touches: the titlebar wordmark, home hero, stat numerals and the empty-canvas mark
render in Doto (all other themes keep Inter via the `--font-doto` fallback); the canvas grid
becomes a white/red dot matrix; wires render as white dashes that turn red while active; the
ETA module's segments read like the Glyph LED strips; the selection, active rail/tab/menu
states and primary buttons carry the signal red; corners go sharp.

Default theme is unchanged (`void`). Choose `nothing` in **Settings → Appearance**.

## 2. The debugging pass — ten defects, all fixed

1. **Version drift, again.** The titlebar host pill hardcoded `v5.0` while every manifest said
   10.x — the exact failure class `src/version.ts` was created to kill, surviving because the
   versionDrift probe only scanned two files. Fixed: `App.tsx` now imports `MJ_VERSION_SHORT`,
   and `probe/theme.test.ts` asserts no `vX.Y` literal survives in the shell.
2. **Passive-wheel zoom.** React registers delegated `wheel` listeners as passive, so the
   canvas's `onWheel` + `preventDefault()` never prevented anything — Ctrl+wheel zoomed the
   host page/WebView alongside the canvas and Chromium logged a passive-listener violation on
   every gesture. Fixed: the canvas now attaches one native `wheel` listener with
   `{ passive: false }` (`src/canvas/Canvas.tsx`).
3. **Dead Grid-snap setting.** Settings exposed "Grid snap (0 = free)", but node dragging,
   library drops and palette adds hardcoded `16`. Fixed: `snapCoord()` reads the pref live;
   0 means free placement.
4. **Minimap painted theme amber in every theme.** The node rectangles hardcoded `#C9A66B`
   and `#555`. Fixed: theme tokens (`--amber`, `--text-4`).
5. **Invisible hover rows in paper.** Menu flyout, window buttons and palette results hovered
   to a literal `#1a1a1a` — a dark blob on the light theme. Fixed: a `--row-hover` token,
   overridden per theme.
6. **Two sources of truth for the theme.** The pre-hydration boot script in `index.html` read a
   private `mj.theme` mirror that only `SettingsPage` kept in sync — change the theme anywhere
   else (or import prefs) and every reload flashed the wrong theme before React mounted. Fixed:
   the boot script reads `mj.editor.prefs` — the same store `getEditorPrefs()` reads — with the
   legacy key honored as a fallback, and the duplicate write is gone.
7. **Stat grid built for four.** `.stat-row` was a 4-column grid; Home renders five stats, so
   the fifth wrapped into a stretched orphan. Fixed: `repeat(auto-fit, minmax(150px, 1fr))`.
8. **Unreadable selection in paper.** `::selection` hardcoded near-black text on the accent.
   Fixed: `color: var(--bg)`.
9. **Stale port-fill dots.** `NodeCard` read connections via `getState()` during render — the
   anchors only repainted when something else re-rendered the canvas. Fixed: subscribed hook.
10. **Escape ignored the canvas context menu.** The app-level Escape closed panels but not the
    right-click menu. Fixed: the canvas listens for Escape itself.
11. **"First workflow" created twice.** React StrictMode deliberately double-invokes effects in
    dev, and the bootstrap effect's two runs both saw an empty workflow list — so a fresh
    install started with two identical "First workflow" rows (and two orphan records in the
    native store). Fixed: the bootstrap is a single module-level promise; the second mount
    rides on the first instead of racing it.

## 3. Version bump — one source of truth, all manifests

`src/version.ts` → **10.1.0**, and `package.json`, `package-lock.json` (both fields),
`src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json` and the README title follow. The v10Page
probe no longer hardcodes the expected release string; it derives it from `MJ_VERSION_SHORT`,
so the next bump cannot silently break it.

## 4. New probe: `probe/theme.test.ts` (17 assertions)

Asserts the thing this release changed cannot regress: every theme advertised in Settings has
a CSS token block and is accepted by the prefs whitelist; the nothing theme carries its real
tokens (#000000, #1B1B1D, #D71921, Doto); the dot-matrix font is genuinely bundled (fonts.css
declaration, variable weight axis, woff2 magic bytes on disk); and no literal release string
survives in `App.tsx`.

## 5. What is NOT proven — stated plainly

- `cargo check` on the Tauri crate still requires the GTK/WebKit stack (see `MJ-10.0-UPGRADE.md`
  §5). V10.1 changes no Rust code.
- The nothing theme is verified by token-presence probes and a rendered build, not by
  screenshots on real hardware — open **Settings → Appearance → nothing** and judge with your
  own eyes.
- The `reviewVisibility` probe still needs a real OpenCode binary on disk; it is unchanged and
  remains environment-gated.
