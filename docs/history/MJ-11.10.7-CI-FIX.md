# MJ 11.10.7 — the fix CI caught

## What happened

CI run #52 (commit `9c26bcb`, the 11.10.5-r1 docs re-cut) failed on `verify (linux)` and
`verify (macos)` while `verify (windows)` went green. This document records the post-mortem in
the same spirit as the rest of the repo: the failure named, the cause proven from logs, and the
fix stated so it can be checked.

## Root cause — proven, not guessed

The failing step was `npm test` (after tsc, cargo check, cargo test and clippy had all passed).
The failing suites were `realExecution.test.ts` and — downstream of it inside `verify/run.mjs` —
exactly one bundled copy of the same suite.

* GitHub's `ubuntu-24.04` and `macos-15` images ship a **`python3` interpreter with no pytest
  package**. `realExecution.test.ts` gated its real-repository section on `command -v python3`
  alone, then ran `python3 -m pytest -q`. The interpreter answered "No module named pytest" and
  exited 1 — an *environment* error the suite recorded as three red assertions.
* The `windows-latest` image ships no `python3` on PATH at all, so the suite skipped that whole
  section and passed — claiming less, but passing. Which is why every pre-merge run looked fine.
* Development machines (and any box with pytest installed) exercised the real path and passed.

One interpreter-package gap, three red assertions, two operating systems, one OS masking it.
Exactly the class of environment lie this project's check-runner exists to prevent — which made
the fix location obvious.

## The fix — two layers

1. **`src/mission/checkRunner.ts` — the product fix.** `runCheck` now probes
   `python3 -m pytest --version` before executing a pytest check. If the package is absent the
   result is `didRun: false` with the named reason *"python3 is present but the pytest package is
   not installed; MJ will not run an install for you, so this check was not performed"* — the same
   honesty contract the `node_modules is absent` refusal already had for npm-family checks. A
   missing test runner is now reported as *unmeasured*, never as a failing suite, for every MJ
   user on every host — not just in our CI.
2. **`probe/realExecution.test.ts` — the gate fix.** The suite no longer confuses "an interpreter
   exists" with "pytest exists":
   * pytest importable → the full real-repo contract runs (green exits 0, red exits non-zero with
     the failure text captured verbatim, dependency-less npm repos refused);
   * python3 without pytest → the suite asserts the **refusal itself**: discovered, `didRun=false`,
     no exit code, reason named — a measured outcome, not a skip;
   * no interpreter at all → an honest, spoken skip;
   * the machine-absolute cargo path (`/home/user/.rustup/toolchains/...`) is replaced by a
     portable `$HOME/.cargo/bin` lookup, so the suite is no longer tattooed to one laptop.

## Gates re-run for 11.10.7 (Node v22.23.2)

```
tsc --noEmit          exit 0
npm test              ALL PROBES SUMMARY: 59 passed, 0 failed
node verify/run.mjs   OFFLINE VERIFY SUMMARY: 58 passed, 0 failed
vite build            exit 0
```

The missing-pytest path is asserted in both directions (refusal and execution), so a runner that
silently changes its Python image flips a named assertion, not a mystery exit code.
