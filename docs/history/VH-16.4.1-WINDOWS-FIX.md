# VH 16.4.1 — Windows fix (what differs from the zip)

> This tree is 16.4.1 **plus the fixes below**. The `v16.4.1` tag was re-cut
> on top of the shipped source so the Windows gates pass. Nothing else was
> touched: to verify, diff the tag against `VOUCH-HARBOR-16.4.1-full.zip` —
> every difference is listed here, file by file.

## Code fixes

1. **`probe/mcpRouter.test.ts` — esbuild spawn made Windows-capable.**
   The rebuild check shelled out to `node_modules/.bin/esbuild`, which
   exists on Windows but is an extensionless shell shim the OS cannot exec
   (ENOENT) — the suite failed on every Windows machine while passing on
   Linux CI. Now resolves `esbuild.cmd` on win32 and runs through the shell
   there. Offline sha256 pin unchanged.
2. **`src/mission/missionLoop.ts` — `loopBusFeed` keeps the bus instance.**
   `subscribe: globalAgentBus.subscribe` detached the method, so the page's
   mount effect called it with `this` = the projection literal and
   `this.listeners.add` threw "Cannot read properties of undefined
   (reading 'add')" — every LoopPage mount crashed into the error boundary
   (proven with stack trace in a real browser on 14.1.1; same line present
   here). Now a closure over the bus instance. All five pages verified
   rendering with 0 console errors on 14.1.1; same one-line shape here.
3. **`verify/suites/*` + `verify/MANIFEST.json` — offline pack rebuilt** from
   the fixed probes via `tools/build-offline-verify.mjs` (the offlinePack
   freshness gate passes: rebuild == shipped).
