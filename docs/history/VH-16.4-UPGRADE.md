# Vouch Harbor 16.4.0 — the drill: the product proving itself on real missions

The reviews kept naming the same remaining gap: *validate on genuinely
external real-world missions, and prove the product under real usage.*
16.4.0 turns that into a product capability: **the drill**. A set of
standard real missions — each a fresh, real git repository with a real
codebase and the repository's **own test command** — dispatched through
the **real mission loop** with **real git** and **real verification**.
The product runs its own acceptance test, on any machine, and stamps the
result with a vouched drill report + attestation digest.

## What shipped

### The drill (`src/vouch/engine/drill.ts`)

Three standard scenarios, each a real repo + real test:

- **`guard`** — a security bug (disabled admins pass authorization);
  the mission must fix `guard.js` so the repo's own `test.js` passes.
- **`maths`** — a failing test that demands a missing `clamp()`; the
  mission must implement it.
- **`impossible`** — the honest-failure scenario: the test demands an
  exact secret constant outside the seat's playbook. The loop must report
  **FAILED** with the real failing test output. **Never a fake pass.**

Every run: fresh `git init` + committed baseline → real mission loop
(real governance arena battery, real git worktrees per seat, budget
ledger, one signed cycle receipt) → unified mission-ledger entry → the
drill's own vouch receipt (origin `"drill"`, `vouch.drill` event with the
real test output tail) → attestation digest (sha256 over the stable
fields: scenario, status, verified seats, seats, cycle, version —
reproducible across runs, not wall-clock).

**The honesty model, stated in the code:**
- REAL: the git repositories (git binary, worktrees), the verification
  (the scenario's own test command, executed for real), the loop
  (governance arena, budget, receipts, ledger), the vouch receipts.
- LABELED: the seats. The built-in drill seat is a deterministic playbook
  — the swappable-brain seam. On a host with real agent CLIs, real crews
  run real missions; the drill proves the *machinery* with a known seat,
  so the result is reproducible on any machine.
- NO FAKE PASSES: `impossible` comes back FAILED with the real test
  output, its repo is **kept for forensics** (the report carries the
  path), and the failure is vouched like everything else.

### The faces

- **Governed tool** — `run_drill` is a real entry in the governed tool
  registry and on the **risky** side: it is a mission, so it pauses at
  the human gate through the single throat (`runVouchToolCall`) like
  every other mission — chat face, MCP face, UI: same gate, same
  receipts, no special path.
- **MCP** — `run_drill {scenario}` over the wire (the governed surface is
  now **20 tools**): pending + handles → `approve_action` →
  `call_status` → PASSED + receipt → `verify_receipt` over the wire.
- **UI** — the **Drill** door under System: the scenario catalog with
  objectives, a Run button (gated), and the persisted drill report ledger
  (status, verified seats, real test output tail, mission id, receipts,
  attestation digest, forensics path on failure).

## 16.4.1 — the provenance patch

A reviewer reading the mission artifacts (not the source claims) found two
stale-provenance defects. Both are fixed and now probe-pinned:

1. **The mission record stamped an obsolete execution version.**
   `buildMissionRecord` hardcoded `mjVersion: "14.1.0"` — a 16.4 mission
   artifact claimed to be produced by a 14.1 core. It now stamps the single
   `VH_VERSION` constant (the same value every other artifact uses), and
   `probe/missionRecord` asserts a freshly sealed record reports the CURRENT
   release — the stale literal can never return silently.
2. **Clean-identity residue in exported text.** The learned-skill manifest
   exported `author: "MJ"`, and the issuer public-key document's prose said
   "this MJ install" while naming only the legacy wire. The author is now
   "Vouch Harbor"; the document names the current `vh-proof-receipt/2` wire
   first and the legacy wire as back-compat, in the clean identity.
3. The drill's MCP tool description no longer carries a hardcoded version
   literal (the surface should not rot on the next release).

No behavior change beyond the version stamp. Same suites, same counts.
