# MJ 11.0 — PROPOSAL — the final version

**The thesis of V11 in one sentence: everything MJ advertises becomes real, everything MJ ships
becomes a verifiable signed artifact, and every seam where MJ touches the outside world speaks a
2026 standard instead of a bespoke parser.**

V11 is framed as the *completion release*, not a feature release. The docs in this tree have been
honest for six versions about what is not proven; V11 is the version that deletes the disclaimers
by doing the work. Three promises define it:

1. **Everything advertised is real.** No echo stubs, no canned capabilities, no "not implemented"
   throws on a surface the UI still renders.
2. **Everything shipped is compiled and installable.** `cargo check` runs in CI on three OSes; a
   tag produces signed installers and a signed auto-update for Windows, macOS and Linux.
3. **Everything speaks standards.** One protocol for driving coding agents (ACP), the current MCP
   spec for the control plane, AGENTS.md for project context in and out, OTel GenAI for
   observability out — all opt-in, all local-first, nothing phones home.

---

## W1 — One wire: ACP replaces the bespoke CLI parsers

**Today.** `src/mission/harnessAdapters.ts` hand-maintains a spawn/parse integration per coding
CLI — nine harness surfaces, of which the Proof page honestly records only **two verified against
real binaries** (Claude Code 2.1.197, OpenCode 1.18.25). Every CLI release can silently break a
parser.

**The 2026 fact.** The Agent Client Protocol (Zed Industries, Aug 2025; co-developed with
JetBrains since Oct 2025) standardizes exactly this seam: JSON-RPC 2.0 over stdin/stdout between
an editor/host and a coding agent, with session management, token streaming, tool-call reporting
and **bidirectional permission requests**. Claude Code, Gemini CLI, Codex and Goose speak it;
Zed and JetBrains ship a shared ACP Agent Registry; 25+ agents and editors participate.

**V11 does.**
- MJ becomes an **ACP client**. A mission seat spawns any ACP-compliant agent through one
  adapter: `session/new`, streamed `session/update` into the flight recorder, tool-call events
  into the evidence panels, and `session/request_permission` wired into the **existing approval
  inbox** (the protocol models what MJ already built by hand).
- The nine bespoke adapters are demoted to fallbacks for CLIs without ACP, marked
  `legacy-adapter` in the Proof page, and deleted one by one as ACP coverage lands.
- The Proof page's "verified against a real binary" table becomes per-adapter honest again —
  one ACP conformance probe instead of nine parsers to re-verify every release.

**Proven by.** `probe/acp.test.ts`: a scripted fake ACP agent (JSON-RPC over stdio) is driven
through plan → permission request → human approval → streamed work → checkpoint, asserting every
event lands in the flight recorder and the approval gate actually gates.

## W2 — A real control plane: MCP 2025-11-25 dispatcher, Tasks, elicitation

**Today.** `control_mcp.rs` advertises **8 tools and implements 1** (`validate_graph`);
`dispatch` is an echo stub — written down in `LOCAL-WORKLIST.md` §5 since V5. `cap.browser`
returns canned navigation, `browser_act` returns false, and the capability still reports success.

**The 2026 fact.** The MCP spec moved: 2025-11-25 ships **experimental tasks** (SEP-1686: durable
requests with polling and deferred results), **sampling with tool calling** (SEP-1577),
**elicitation** with standard enums and URL mode, OAuth Client ID Metadata Documents, and an
extensions framework; the 2026-07-28 release candidate adds a stateless core, multi round-trip
requests, MCP Apps and a formal deprecation policy. The MCP Registry passed ~2,000 servers.

**V11 does.**
- All 8 advertised tools are implemented for real against the existing Rust modules (graph,
  scheduler, db) — or a tool is delisted until it exists. Advertisement equals behavior.
- `run_workflow` becomes an MCP **task**: clients poll/collect long-running workflow state per
  SEP-1686 instead of a blocking call that lies about progress.
- **Elicitation** is bridged into MJ's approval inbox: an MCP server that asks a question
  surfaces as a first-class MJ approval with risk classification, not a silent default.
- `cap.browser` is deleted or made real through a controlled fetch/render surface. The lie is the
  defect; either honest state is acceptable, `success: true` is not.
- The external MCP catalog gains per-server risk classes that flow through `riskPolicy.ts` like
  any other action — an MCP tool call is an action, classified, gated, recorded.

**Proven by.** `probe/controlPlane.test.ts`: an external JSON-RPC-over-stdio client initializes,
lists tools, starts a workflow as a task, receives an elicitation on a HIGH-risk step, approves
it, and collects the completed result. Plus a negative probe: an unadvertised tool call is
refused with a protocol error.

## W3 — Enforcement, not promises: OS sandbox per risk tier

**Today.** `riskPolicy.ts` classifies actions into CRITICAL/HIGH/MEDIUM/LOW with an ordered
rule table — good — but enforcement beyond the process boundary is delegated to flags the agent
is asked to honor.

**The 2026 fact.** OS-level agent sandboxing went mainstream: Claude Code ships `/sandbox`
(Seatbelt on macOS, bubblewrap on Linux, plus an HTTP/SOCKS5 proxy enforcing a network
allowlist), Codex CLI defaults to Landlock + seccomp on Linux and Seatbelt on macOS, and the
ecosystem converged on credential-path blocking (35+ paths) and env-token scrubbing (28+
patterns) as baseline hygiene.

**V11 does.**
- MJ itself wraps every spawned agent process in an OS sandbox chosen by the mission's risk
  policy: **bubblewrap + Landlock** profiles on Linux, **Seatbelt** profiles on macOS, a
  documented WSL2 story on Windows. Filesystem writes scoped to the mission workspace + session
  temp; network **deny by default**, allowlist per tier; credential paths and token-shaped env
  vars scrubbed from the child environment for every tier above LOW.
- The sandbox profile for each seat is shown in the UI **with proof, not assertion**: at seat
  start MJ runs two canary commands (write outside the workspace, connect to a blocked host) and
  records that they *failed*. The Proof page shows "enforced: measured" per seat.
- Checkpoint/rollback gains teeth: a CRITICAL-classified mission cannot even start without a
  checkpoint on disk, because the sandbox makes mutation recovery cheap and verifiable.

**Proven by.** `probe/sandbox.test.ts` (Linux CI): spawn the sandboxed wrapper, assert the
canaries fail, assert the workspace write succeeds, assert the env scrub removed every token
pattern from the child's environment.

## W4 — Portability: AGENTS.md in, OpenTelemetry GenAI out

**Today.** Role packs and procedures are MJ-internal knowledge. The flight recorder is a private
event log. Neither is useful outside MJ, and MJ ignores context files the rest of the ecosystem
already standardizes.

**The 2026 facts.** `AGENTS.md` — plain Markdown, no schema — is read natively by 30+ coding
tools, stewarded by the Agentic AI Foundation under the Linux Foundation, and adopted by 60,000+
repositories with nearest-wins nesting semantics (Codex's own monorepo ships 88 of them).
OpenTelemetry's GenAI semantic conventions define `invoke_agent` / `execute_tool` spans and
`gen_ai.*` attributes — still honestly **Development** status, but already emitted by Claude Code
(beta) and consumed natively by Datadog and Langfuse.

**V11 does.**
- **AGENTS.md round-trip.** MJ *reads* existing AGENTS.md files (nearest-wins from the workspace
  root) into mission planning context, and *writes* one per mission workspace from the plan:
  build/test commands, boundaries, the done-when contract. Every harness — ACP or legacy — gets
  the same ground truth, and humans can read and correct it in their editor.
- **OTLP export, opt-in, local-first.** The flight recorder exports OTLP-JSON traces using
  `gen_ai.*` spans to a user-configured endpoint or a local file. Nothing sends anywhere by
  default; the setting is off in every default profile. The Proof page labels the conventions
  "Development" — the same honesty rule the OTel SIG itself applies.

**Proven by.** `probe/agentsMd.test.ts` (round-trip on a temp repo) and
`probe/otelExport.test.ts` (exported JSON validates against the OTLP schema; spans carry the
mission/checkpoint IDs that make the flight recorder's "why" answerable in an external viewer).

## W5 — Ship it: CI, signed installers, auto-update

**Today.** The tree's own §5 admits it: "`cargo check` has never run on the full Tauri crate";
"no installer has ever been produced". The app exists as source with a build *worklist*.

**The 2026 fact.** Tauri v2's updater is a solved, documented path: minisign-keypair signing at
build time, static-JSON endpoints on GitHub Releases (Tauri Action generates the feed), and an
in-app updater plugin — the same mechanism thousands of Tauri apps ship with.

**V11 does.**
- GitHub Actions matrix (ubuntu-22.04, macOS arm64+x86_64, windows-latest) running, on every
  push: `cargo check/test/clippy` on the real crate with the real GTK/WebKit deps, `tsc --noEmit`,
  **every probe**, `vite build`. A tag additionally runs `tauri build` with
  `TAURI_SIGNING_PRIVATE_KEY` and publishes installers + `latest.json` via Tauri Action.
- The app gains an opt-in "check for updates" action using `tauri-plugin-updater`, verifying the
  minisign signature before anything else. Off by default; no phone-home.
- `probe/versionDrift` grows one tooth: `Cargo.lock`'s own package version must equal
  `MJ_VERSION`, so the lock can never silently disagree again.

**Proven by.** A green CI run on the three OSes and three signed artifacts attached to a release.
This is the single biggest trust upgrade available: the phrase "compiled against a stub" never
needs to be written again.

## W6 — Close the honesty ledger: zero stubs, four verified harnesses

**Today.** Named stubs since V5: `workflow_versions`, `workflow_version_restore`, `skill_touch`,
`evaluation_save`, `evaluation_history`, `suite_list`, `suite_save`, `run_request_take`; skill
usage tracking literally throws "not implemented" (`src/ipc/client.ts:213`). Two of nine harness
surfaces verified against real binaries.

**V11 does.**
- Every stubbed command is implemented against the SQLite store that already exists in
  `db.rs` — versions, evaluations, suites, run requests, skill usage — or the surface is deleted
  from the UI. The V11 rule is absolute: **no advertised surface may throw "not implemented."**
- The Proof page gains a **stub ledger** section: a table that must render empty, generated by
  scanning for the stub registry at build time, and asserted empty by a probe.
- `reviewVisibility`-style live-binary verification is extended to at least four harnesses
  (Claude Code, OpenCode, Codex, Gemini CLI via ACP where available), each recorded with its
  binary version, or its Proof-page row drops to "unverified" automatically.

**Proven by.** `probe/stubLedger.test.ts` and the extended live-binary matrix in CI.

## W7 — Experimental, clearly fenced: missions as A2A agents

A2A joined the Agentic AI Foundation alongside MCP in August 2026, with 150+ organizations, all
three major clouds, and Agent Cards for discovery. MJ's shape — a mission runner that plans,
gates and audits work — maps naturally onto an A2A server that lets *external* orchestrators
delegate tasks into MJ, and onto consuming a remote A2A agent as one mission seat.

V11 includes this **only** as a fenced experimental module: off by default, its own capability
file, its own Proof-page section, and strictly downstream of W1–W6. If it threatens the schedule,
it ships as V11.1. A "final version" that slips for an optional protocol integration would not be
final.

## Definition of done — the V11 contract

1. CI green on three OSes: `cargo check/test/clippy`, `tsc`, all probes, `vite build`.
2. A tag produces signed installers + a working signed auto-update for Windows, macOS, Linux.
3. The stub ledger renders empty; no IPC surface throws "not implemented".
4. The ACP probe passes; at least four harnesses verified against real binaries in CI.
5. Sandboxed seats prove enforcement with failing canaries, not promises.
6. AGENTS.md round-trips; OTLP export validates; both off/opt-in by default.
7. Every probe that was green in 10.1 is still green — the 320 assertions are the floor.
8. `MJ-11.0-UPGRADE.md` written in this tree's voice: what is proven, what is not, plainly.

## What V11 will NOT do

No cloud service, no sync, no accounts, no telemetry, no Electron rewrite, no plugin marketplace,
no multi-tenant web mode. MJ stays a local-first desktop workstation; every protocol surface it
gains in V11 is opt-in, off by default, and honest about its status. Subtract, don't add — the
final version is the one with nothing left to apologize for.
