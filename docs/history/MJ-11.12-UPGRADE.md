# MJ 11.12 — MOSAIC-Ω alignment + Varkha extracts, upgrade notes

11.12.0 shipped the MOSAIC-Ω extract prescribed by docs/MOSAIC-OMEGA-COMPAT.md;
11.12.1 closes the two findings of the 9.75/10 review and adds the four small
Varkha extracts from docs/VARKHA-COMPAT.md. No new subsystems: everything below
reuses the 11.11.1 experiment and the receipt-grade proof architecture.

## 11.12.0 — the epistemic layer

- **Belief store** (`src/mission/belief.ts`): claim / class (known, probably,
  uncertain, contradicted, unknown) / confidence / source / deps / evidence.
  External claims cap at "probably"; only verified local execution may be
  "known"; same-subject disagreements become "contradicted" and surface with a
  verify-before-acting warning. Predictions are labelled NOT evidence and never
  enter lessons, arm scores, or receipt measured facts.
- **Proof-carrying actions** (`src/mission/actionPacket.ts`): signed pre-action
  packets (intent, belief digest, plan step, prediction, risk, permission,
  rollback, verification). SHA-256 canonical digest + Ed25519 where available.
- **Causal memory** (`src/mission/lessons.ts`): lessons carry decision /
  action / observation / outcome edges; `retrieveCausal` answers "what happened
  when we tried X" with zero similarity bleed.
- **Framework-as-experiment-arm** (`src/mission/selfImprove.ts`): fifth strategy
  dimension `mosaic`; the extract rides only on runs whose governing strategy
  has it on, so the online experiment adopts or retires it with numbers.
- **probe/mosaicAlign.test.ts**: 20 assertions on the two rules (predictions are
  not evidence; proof-carrying actions).

## 11.12.1 — review fixes + Varkha extracts

- **Cryptographic execution boundary** (review fix #1): TeamExecutor now runs
  `verifyActionPacket` (digest + signature) FIRST and aborts on mismatch, THEN
  `packetAllowsExecution`, THEN executes. The report carries
  `actionPacket.verified`. The runtime proves "this exact signed packet says
  this action is allowed".
- **Regenerated provenance** (review fix #2): verify/BUILD-INFO.txt is rebuilt
  from the certifying tree and names no older release as the pack's origin.
- **SCAR before PRECEDENT**: briefings retrieve matching failure lessons first.
- **Write asymmetry**: agent-inferred beliefs about the user stay pending until
  human approval (`needsApproval` / `approveBelief`); user-stated preferences
  brief immediately.
- **Attenuated seat envelopes**: per-seat scope (role, write:worktree or
  read:review-snapshot, spend:capped-by-ledger) derived from the run's packet,
  recorded on the report.
- **Step-repetition signal**: identical consecutive turn signatures per seat
  surface as a SUGGEST-level deliberation signal; never auto-acted, never fed
  to the strategy experiment.
- **Ablation clarity**: `diffDims` + varkhaAlign pin that every candidate
  differs from its parent by exactly one dimension — the mosaic experiment is
  a paired toggle against the same parent configuration.
- **probe/varkhaAlign.test.ts**: 17 assertions.

## MJ 11.12.2 (this point release) — external-review fixes: governance becomes real artifacts

1. **Authority Envelope** (`src/mission/custody.ts`): every local-team run can carry a signed
   envelope with a human principal, scope, expiry and a delegation chain. Seats can only
   *attenuate* — children hold strict subsets of the parent's scope and can never outlive it.
   Revocation is instant; verification is cryptographic. Pre-11.12.2 callers proceed under the
   gate policy alone — the new boundary applies where the executor receives an envelope.
2. **Typed Ledger** (`src/mission/ledger.ts`): every memory record is one of SCAR / PRECEDENT /
   DOCTRINE / RECOURSE / STANCE with a write-permission matrix — agents may never write DOCTRINE
   or install RECOURSE (the experiment and humans do). This is what the Audit page displays.
3. **One human approval queue** (Evolution page card): pending skill proposals and beliefs MJ
   inferred about the user live in one structured inbox next to the mission gates on Control.
4. **Plain-language Audit page** (nav "Audit"): receipts you can verify, the current experiment,
   MJ's five memories about you, and its beliefs — all live-derived from local stores, none
   hardcoded.
5. **Step-repetition escalation wired** (`src/mission/escalation.ts`): identical consecutive turn
   signatures are measured (MAST's ~15.7% failure class); at >=3 the UI *suggests* deliberation —
   never automatically.
6. **governanceAlign probe**: pins envelope subset/expiry/revocation/tamper and the ledger matrix.
7. Counts: probe suites 62 -> 63; offline bundles 61 -> 62. Gates on Node 22: tsc 0 / vitest 63 /
   vite 0.

## MJ 11.12.3 (this point release) — governance becomes mechanical

The 9.9/10 review of 11.12.2 named two gaps; both are now enforced, not documented:

1. **Human principal enforced.** `issueRootEnvelope` refuses to sign for any
   principal that does not match `human:<id>` (`HUMAN_PRINCIPAL_RE`);
   `attenuate` refuses to delegate from a non-human root; `verifyEnvelope`
   flags hand-rolled envelopes. Pinned by probe.
2. **Ledger matrix enforced at the store boundary.** `enforceWrite` is called
   by `saveLessons` (SCAR/PRECEDENT per record), `saveSkills` (approved
   records = RECOURSE), `saveBeliefs` (STANCE) and `saveImprovement`
   (RECOURSE) BEFORE anything persists. Agents may propose freely; they
   cannot mechanically install approved skills, adopt strategies or write
   house rules.
3. **Focus on the build.** FUNDING.md, the pitch deck and the product brief
   are removed; CHANGELOG now carries 11.11.1 through 11.12.3.
