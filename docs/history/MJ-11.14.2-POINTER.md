# MJ 11.14.2 — THE PRIVACY GUARD (2026-09-07)

> 11.14.1 built the Capability Channel. 11.14.2 faces the reviewer's decisive
> critique: aggregate-only does NOT automatically mean privacy-safe — narrow
> or repeated aggregate queries can reconstruct rows. The answer is
> DatasetPolicy, enforced before any computation, with every refusal in
> words and probe-pinned.

The 11.14.2 release notes ship in upstream `docs/history/MJ-11.14-UPGRADE.md`
and the regenerated `verify/BUILD-INFO.txt`. This file is the discoverable
pointer in-repo; both ship with the source.

## What landed (over 11.14.1)

- **DatasetPolicy (`src/mission/capability.ts`).** Enforced BEFORE any
  computation: field policy (only declared fields aggregate), minimum cohort
  size (small aggregates refused — they can expose individuals), a hard
  per-window query budget (refusals count too — probing IS the attack), and
  bounded precision (answers never carry more decimal grain than policy
  allows).
- **Probes:** `capabilityAlign` 11 → 18 assertions (cohort guard, off-policy
  field, budget exhaustion, window reset, rounding, cohortSize metadata);
  guardrail manifest line 13, `guardrailAlign` 12 → 13.
- **`docs/ENTERPRISE-THESIS.md` tightened.** WhatsApp selective-sharing
  analogy applied to enterprise computation; competitor honesty (the moat is
  the combination — capability + policy + cryptographic receipts + agent
  execution — not "data stays local"); a section facing the hardest problem:
  aggregates can leak.
