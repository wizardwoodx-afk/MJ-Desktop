# MJ 12.1 — UPGRADE notes (Knowledge Forge)

This file exists per the probe contract (theme probe: every `MJ-x.y` ships
`MJ-x.y-UPGRADE.md`). Full notes live in `CHANGELOG.md` row 12.1.0,
`docs/history/MJ-12.1.0-POINTER.md`, and the module header of
`src/mission/knowledgeSkills.ts`.

## What changed for the user

The Mission Loop screen gains the **Knowledge forge** card: paste a document
(chapter, runbook, markdown — or a SKILL.md produced by a book-to-skill-style
distiller), optionally pick a local harness for an LLM distillation pass, and
convert it into a **proposal**. Approve it and it becomes a `[knowledge]`
skill that rides every future mission briefing; discard it and nothing
changes. Books and internal docs become reusable agent knowledge — with
provenance, a human gate, and no claim that the loop "measured" any of it.

## What changed under the hood

- `src/mission/knowledgeSkills.ts` — the forge: mechanical extractor + LLM
  pass through MJ's own harness CLIs + knowledge proposal store
  (`mj.knowledgeSkills.v1`).
- `src/mission/skillEvolution.ts` — `SkillProposal.source` gains
  `"knowledge"`.
- `src/mission/missionLoop.ts` — re-exports the forge API (the page imports
  the engine only).
- `src/pages/LoopPage.tsx` — the Knowledge forge card (distill →
  approve/discard).
- Probes: new `knowledgeSkills` 34/34; navAlign 42/42 (forge is engine API).

## Honesty notes

- LLM distillation runs only through local harness CLIs; in the browser
  edition the LLM pass is off and the card says so.
- Knowledge is human-approved external knowledge. It never claims measured
  effect and never enters lesson/autonomy state by itself.

# MJ 12.1.1 — patch notes (appended to the 12.1 upgrade record)

The 12.1.0 review (9.6/10) found two real problems; 12.1.1 closes both:

1. **Renderer crash**: provenance used Node's `Buffer`; the browser/Tauri
   renderer would throw. Now TextEncoder byte length — renderer-safe, and a
   probe forbids `Buffer` from returning to the module.
2. **Data handling overclaim**: the LLM pass sends the document to the
   selected harness's configured model provider (cloud by default). Every
   proposal now records `dataHandling: local | provider` by what actually
   happened, and the UI discloses it before a cloud pass.

Wording narrowed to "documents → structured knowledge proposals, with
provenance and human approval". Totals unchanged: 75 live suites /
74 offline bundles; knowledgeSkills 44/44.
