# MJ 11.14 — Upgrade notes

## MJ 11.14.0 (this release) — the Egress Gate: the enterprise seed

The enterprise thesis, made mechanical. Company data lives on employees'
laptops; the cloud is a switchboard — channels, coordination, approvals,
audit — never a warehouse. Like sending one photo on WhatsApp instead of
uploading the gallery: only the chosen item crosses the boundary, to the
chosen recipient, by explicit human choice.

MJ enforces the thesis on the machine it already runs on:

1. **The Egress Gate** (`src/mission/egress.ts`). Nothing leaves the machine
   unless a human click issues a fresh, short-lived authority envelope scoped
   `egress:share`. No envelope, an expired envelope, a revoked envelope, a
   wrong-scope envelope, or a non-human principal are each refused in words —
   refusal is a normal, named outcome, never a silent failure.
2. **The Egress Ledger.** Every authorized departure lands as a receipt: item
   kind + name + sha256 of exactly what left, recipient, authorizing
   principal, envelope id, and the receipt's own digest. `verifyEgressLedger`
   recomputes every digest — any edit to what-left-the-machine is detectable
   and named. This is the CISO audit trail, generated not narrated.
3. **The Audit page** shows both: the export flow now passes through the gate
   (the Proof Dossier itself cannot leave without authority + receipt), and a
   new card lists every departure with a one-click ledger integrity check.
   The guardrail manifest gains its eleventh line.

What this is: the LOCAL primitive the enterprise product depends on. The
multi-node channel system (encrypted laptop-to-laptop channels, cloud relay
that sees coordination and receipts but never payloads, org console) is the
roadmap built ON this gate — every future channel departure will pass the
same check and leave the same receipt.

What this is not: it does not move data to a cloud, and it does not pretend
to. Data minimization by architecture.

New probe: egressAlign (8). guardrailAlign grows 10 -> 11. Counts: 67 live
suites / 66 offline bundles. Gates on Node v22.23.2: tsc 0, 67/67 live,
66/66 offline, vite 0.

## MJ 11.14.1 (this point release) — the Capability Channel

The enterprise thesis, working on one machine. The upgrade from "share a
file" to "expose a capability without exposing the data":

1. **Capability requests** (`src/mission/capability.ts`): a remote colleague
   asks for an approved OPERATION (aggregate whitelist — count / sum / avg /
   max — structurally incapable of returning raw rows) on data that lives on
   THIS machine. The computation runs where the data lives, under a
   human-signed envelope scoped `capability:run`. Missing, expired, revoked,
   wrong-scope, non-human, off-whitelist and unknown-dataset requests are
   each refused in words.
2. **Only the answer travels**: the result is digest-stamped and leaves
   through the Egress Gate as a `capability-result` receipt. Raw rows never
   enter the answer — the probe proves the region names never cross the
   boundary.
3. **docs/ENTERPRISE-THESIS.md** — the validation artifact for the platform
   direction: cloud control plane, endpoint data plane, capability-not-data,
   the receipts moat, honest model choice (endpoint processing now,
   privacy-preserving compute later), staged roadmap, and what must be
   validated with buyers before cloud infrastructure is built.

The Audit page gains the capability demo card; the guardrail manifest reaches
twelve lines. New probe: capabilityAlign (11); guardrailAlign 11 -> 12.
Counts: 68 live suites / 67 offline bundles. Gates on Node v22.23.2: tsc 0,
68/68 live, 67/67 offline, vite 0.
