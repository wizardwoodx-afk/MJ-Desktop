# Vouch Harbor 16.3.0 — the gated, reversible meta-loop (M6)

**The last major piece of the roadmap.** From this build, Vouch Harbor can
propose changes to its *own* control plane — and every such change is
proposed in words, simulated, human-gated, receipt-vouched, and
reversible. This is the milestone that decides whether a self-improving
governance layer is a feature or a loop. It is a feature, because all five
holds are pinned by `probe/metaLoop` (suite #87).

## What shipped

### M6 — the meta-loop (`src/vouch/engine/meta.ts`)

The product's self-change surface is deliberately small:

- **`risk.tier`** — move a capability from safe → risky, i.e. *tighten*
  the gate. The meta-loop may **never loosen**: a risky→safe demotion is
  refused in words (and the refusal is vouched). Loosening happens only by
  reverting the change that tightened — and the revert is itself gated +
  vouched.
- **`preference.set`** — add a standing preference (applied by RECALL to
  future runs); revert removes it.

What it deliberately does **not** touch: the receipt protocol, the gate
primitive itself, the brain, the code. Those change by humans writing
code, with git — not by the product at runtime. That boundary is stated in
the code and documented here on purpose.

### The five properties (all probe-pinned)

1. **Proposed in words** — a reason is mandatory; the human gate decides
   on those words. Missing reason → refusal in words, vouched.
2. **Simulated** — a dry-run prediction (what will exist when this is
   done) rides into the gate and into the receipt.
3. **Human-gated** — the *same* gate primitive as every risky action in
   the product. The **revert is gated too**: a revert changes governance,
   so it pauses like everything else.
4. **Vouched** — applied, denied, refused, reverted: every decision mints
   a receipt (origin `"meta"`, `vouch.meta` event with the full diff,
   verdict) that verifies offline. The original change carries the
   revert's receipt id when reverted.
5. **Reversible** — revert restores the exact previous state. Reverts
   are terminal (a revert cannot be reverted — propose a new change).

The strongest pins are **behavioral**: after a `risk.tier` tightening is
applied, a call to that tool through the governed executor (`M3`)
*actually pauses at the human gate*; after the revert, it runs freely
again. The control plane changed for real — and changed back. Same proof,
over the wire: a `clock` call that completed freely, gates after the wire
tightening, and is free again after the wire revert.

### The faces

- **MCP** — three new tools (the governed surface is now **19**):
  `meta_propose {kind, target, reason}` (non-blocking: pending + change
  id + approval handle), `meta_status {changeId?}` (the ledger),
  `meta_revert {changeId}` (gated, vouched, terminal).
- **UI** — the **Meta loop** door under System: the current gated
  surface, the proposal form (tighten a tool / add a preference, with
  the reason in words), and the self-change ledger with status, diff,
  reason, decision and receipts, plus a gated **Revert** on applied
  changes. The decision itself is made on **the one gate** (the Vouch
  face) or over MCP — one gate, every decision.

## The refusal book (what the loop refuses in words, and vouches)

- demotions / any loosening proposal
- tightening a tool that is already at the maximum gate
- reverts of unknown ids, of non-applied changes, and of reverts
- unknown kinds, empty reasons, unknown tools, missing preference targets
