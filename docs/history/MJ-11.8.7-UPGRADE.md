# MJ 11.8.7 — DE-VENDORING + SINGLE-RELEASE BUMP

> This release is the direct result of the full functional review, and it ships two things
> as one change so it can be pushed to GitHub as a single upgrade:
>
>   1. The app has been **de-vendored** — the external agent codebase that was bundled is
>      gone, so MJ no longer ships another project's agent files (or their attribution
>      inside the app).
>   2. The version is bumped **11.8.5 → 11.8.7** across every manifest.

## 0. Why de-vendor

The audit found that MJ **never actually executed** the vendored agent code. It was only
referenced three ways:

- a dead constant `BUNDLED_SKILLS_ROOT` (exported, never imported)
- an env var `HERMES_AGENT_REPO` (never read by the Python bridge)
- a `vendor` label string and file-header comments

All the real behaviour — parsing/validating/reassembling the `SKILL.md` skill format and
the evolution fitness/constraints gating — was **already MJ's own TypeScript**. Removing
the bundled external project is therefore a pure lift: it de-bloats the installer and makes
the "MJ is its own agent runtime" claim visible rather than hidden behind a vendored
codebase.

## 1. What was removed

| Path | Files | Size | Why removable |
|---|---|---|---|
| `vendor/hermes-agent` | 603 files | ~12 MB | Never executed; only a path/env string + comments |
| `vendor/hermes-agent-self-evolution` | 30 files | ~252 KB | Logic already ported into MJ's own TS engine |

**Vendor total: 20 MB → 8.3 MB.** What remains is genuinely needed at runtime:
`vendor/mcp-servers-reference`, `vendor/mcp-github`, and MJ's own `evolution-service`.

## 2. Source changes

- `src/domain/hermesSkill.ts` — header now states it is MJ's own implementation; removed
  the dead `BUNDLED_SKILLS_ROOT`; `vendor` label → `"mj"`.
- `src/domain/evolutionEngine.ts` — header rewritten to MJ's own engine; removed the
  vendored-file "source of truth" references.
- `src/pages/EvolutionPage.tsx` / `src/pages/SettingsPage.tsx` — UI copy now says
  "MJ's own engine" / "Bundled runtime" instead of naming the vendored project.
- `src/ipc/client.ts`, `src-tauri/src/commands.rs` — the health `vendors[]` list now only
  names the two MCP server sets.
- `src-tauri/src/hermes.rs` — dropped the `HERMES_AGENT_REPO` env var; `health()` now
  reports MJ's own `evolution-service` path.
- `VENDOR.md`, `NOTICE` — rewritten so only the two runtime MCP server sets (and MJ's own
  service) are declared third-party.

## 3. Version

`MJ_VERSION = "11.8.7"` everywhere the version-drift gate checks:

- `src/version.ts`
- `package.json`, `package-lock.json` (top-level + `packages[""]`)
- `src-tauri/Cargo.toml`
- `src-tauri/tauri.conf.json`

`MJ_VERSION_SHORT` stays `11.8`, so `MJ-11.8-UPGRADE.md`, the doc titles, and the CI
`release.yml` body remain valid — this is a patch-line bump within the same minor.

## 4. Verification

- `npm run typecheck` — clean
- `npm run build` — clean, no warnings
- `npm test` — **40/40 suites** passed
- `node verify/run.mjs` (offline gate) — **39/39** passed
- Live browser boot — **0 console/page errors**; Evolution & Settings pages render the new
  "MJ's own engine" / "Bundled runtime" copy.

> The offline pack was regenerated (`node tools/build-offline-verify.mjs`) so the
> byte-pinned `verify/suites/` bundles reflect the change — this is the correct way to
> keep the anti-fabrication freshness gate green.

## 5. Kept, deliberately

`vendor/mcp-servers-reference` and `vendor/mcp-github` remain vendored and credited. They are
**real runtime servers MJ spawns** (Filesystem, Git, Memory, GitHub, etc.) — removing them
would break the MCP Hub. Their MIT/Apache-2.0 licences stay verbatim in `vendor/` and
`NOTICE`. The PolyForm Noncommercial `LICENSE` for MJ itself is unchanged.

npm run tauri dev   # native desktop (needs Rust 1.80 + platform deps)
npm run tauri:build # .nsis / .dmg / .appimage installers
