# MJ 12.0.0 — ONE ENGINE (the Mission Loop)

*Release pointer. Full notes live in the CHANGELOG row and in the code the row
describes; this file is the history pointer naming what changed and where.*

## The release in one paragraph

Reviews of 11.14.x were right twice: 11.14.10 organized the product's shelves,
and 11.14.11 cleaned the release hygiene — but the app was still "different
productions inside a single app": TEAMS (a 17-tab page), team self-evolution
(its own store), the feedback loop (its own page cards), adaptive learning
(eight separate stores on the Evolve page) and agent communication (its own
tab). **12.0 merges them into ONE engine.** One module
(`src/mission/missionLoop.ts`) now owns the whole cycle —
**COMPOSE → DISPATCH → COMMUNICATE → EXECUTE → GATE → ADAPT** — and one screen
(the Mission Loop page) is the product. The six-stage lifecycle MJ taught as
navigation since 11.14.10 did not disappear: it became the engine's real phase
rail, executed instead of narrated.

## What was merged (feature → engine phase)

| Pre-12.0 feature | Its store/page | In 12.0 it is |
|---|---|---|
| Teams (crews, roles, harnesses) | TeamsPage (17 tabs) | the `team` argument of `runMissionLoopCycle` + the Crew panel on the Loop page |
| Team self-evolution (seat candidates) | `teamEvolution` store + TeamsPage tab | folded from the cycle's seat signals; candidates queue to the HUMAN GATE on the Loop page |
| Feedback loop (gate verdicts → next run) | verifyGate + pages | the loop's GATE phase: the run's own verdicts ARE the feedback; nothing is graded by the loop |
| Adaptive learning (bandit, elastic, lessons) | autonomyStore/lessons/… (8 stores) | folded by ADAPT into the shared stores through the engine — the page reads the engine, never the stores |
| Communication (inter-agent bus) | channel tab | DISPATCH + COMMUNICATE publish every seat's dispatch and event on role channels, live in the Loop page |

## The product surface

Five doors, from `src/app/nav.ts` (PageKind trimmed to exactly these):

1. **Mission Loop** — the engine (one screen: run deck, crew, bus, human gate,
   cycle ledger with receipts, adaptation strip).
2. **Workflows** — design what the engine runs.
3. **Proof** — signed receipt vault.
4. **Audit** — guardrail manifest + ledgers.
5. **System** — connectors, providers, browser, preferences.

Legacy feature pages (home, teams, missions, control, mcp, browser, providers,
executions, observability, evolution) remain in the source tree only where
probes still exercise them and are **not navigable** — no orphan doors.
