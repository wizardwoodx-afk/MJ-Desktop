# MJ 11.14.1 — THE CAPABILITY CHANNEL (2026-09-07)

> 11.13.0 made governance market-facing. 11.14.1 makes it enterprise-shaped:
> expose a capability without exposing the data. Approved aggregate
> operations run where the data lives; only the digest-stamped answer
> leaves, through the Egress Gate. Plus `docs/ENTERPRISE-THESIS.md` — the
> validation artifact for the platform direction (cloud control plane,
> endpoint data plane, receipts moat, honest model choice, staged roadmap).

The 11.14.1 release notes ship in upstream `docs/history/MJ-11.14-UPGRADE.md`
and the regenerated `verify/BUILD-INFO.txt`. This file is the discoverable
pointer in-repo; both ship with the source.

## What landed (over internal 11.14.0)

- **Capability Channel (`src/mission/capability.ts`).** Approved aggregate
  operations only (count/sum/avg/max whitelist), computed where the data
  lives under a human-signed `capability:run` envelope. Only the
  digest-stamped answer leaves — as a capability-result receipt through the
  Egress Gate (`src/mission/egress.ts`). Raw rows never enter the answer
  (probe-proven).
- **Pattern provenance (`src/mission/patterns.ts`).** Code-level guardrails
  pinned at the source level, not just the runtime.
- **`docs/ENTERPRISE-THESIS.md`.** What buyers must validate before cloud
  infrastructure is built. The honesty section (endpoint processing now,
  cloud later, staged) is the strongest trust signal in the tree.
