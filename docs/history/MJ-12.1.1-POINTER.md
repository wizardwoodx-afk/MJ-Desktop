# MJ 12.1.1 — Knowledge Forge honesty fixes

*Release pointer. Full notes live in the CHANGELOG row (12.1.1); this file
names what changed and where.*

## 1. Renderer crash fixed (`src/mission/knowledgeSkills.ts`)

`provenance.byteLength` used Node's `Buffer.byteLength(content, "utf8")`.
Probes run under Node so the suite passed — but the browser/Tauri renderer
has no `Buffer`, and every real distill would throw `ReferenceError: Buffer
is not defined`. Now: `new TextEncoder().encode(content).byteLength` (the
codebase's own renderer-safe pattern). The probe scans the module source and
fails if any Node-global `Buffer.` ever returns.

## 2. Data-handling claim corrected

12.1.0's "no content ever leaves the machine" was false for cloud harnesses:
invoking Claude/Codex/OpenCode sends the document (in the prompt) to that
harness's configured model provider — Anthropic/OpenAI/etc. under the
provider's own terms; only a locally-configured model keeps it on-machine.

Now every proposal records **`dataHandling: "local" | "provider"`** set by
what actually happened:
- mechanical extractor → `local`
- LLM pass, binary not found (never invoked) → `local`
- any invoked CLI → `provider` — even when the output was garbage or the
  call crashed (the content DID go to the provider)

The Loop page discloses the provider-send inline whenever a cloud pass is
selected and shows a `data: sent to provider` / `data: local` chip on every
proposal card.

## 3. Wording narrowed

"books → skills, the provable way" overstated: provenance and governance are
provable; the extracted knowledge's correctness is not (a book can be wrong,
an LLM can misunderstand — approval is governance, not proof). The feature
is positioned as **documents → structured knowledge proposals, with
provenance and human approval**.
