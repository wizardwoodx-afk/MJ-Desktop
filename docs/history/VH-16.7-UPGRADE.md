*Vouch Harbor 16.7.0 — the accountable agent OS (govern · execute · verify · learn).*

The hardening sequence, item 2: **real external-model validation.** Three

## 1. The official client speaks to our server (probe #90: `mcpSdkClient`)

16.6 pinned the WIRE against the official JSON Schemas. 16.7 pins the WIRE
against the official CLIENT: the **`@modelcontextprotocol/sdk` (v1.30.0,
pinned devDependency — the spec's own client library, written by the MCP
maintainers)** drives the REAL server over real stdio. Its latest protocol
is 2025-11-25 — which our server advertises as a supported legacy revision —
so the suite proves the dual-era claim from the outside:

- successful `connect()` is itself the version-negotiation proof (the SDK
  only accepts a protocol version it knows — a server that answered the
  modern revision would have been rejected);
- `listTools()` sees the full 20-tool governed surface;
- safe calls complete with real output;
- the **human gate end to end over the official client**: risky call →
  in-band gate → `approve_action` → `call_status` → executed → the receipt
  verifies (`VALID`); a denial executes nothing (checked on disk);
- honest refusals surface as `isError` results, in words.

The SDK is a devDependency by design — a conformance tool, never product
runtime (probe-pinned).

## 2. The real-model seam: `run_drill` can run on a REAL model

The drill's built-in seats are deterministic and labeled as such — they
validate the machinery. 16.7 adds the seam for validating an actual model:

- **`runDrill(scenario, {harness})`** — the seats dispatch to that
  harness's REAL CLI (the loop spawns the real bin; the report and the
  vouch receipt label the seat `REAL seat: <name> (bin <bin>)`).
- **Honest refusal, never a silent fallback** — an unknown harness or a
  harness whose CLI is not on PATH is refused in words (no report, no
  fake "real" run). Pinned in-process, over the wire (gate → approve →
  refused, `ok=false`), and in the tool's own description.
- **The MCP face exposes it**: `run_drill` gains an optional `harness`
  argument (surface stays 20 tools; no new door).
- **`tools/external-model-validation.mjs`** — the standing validation
  mechanism: it inventories the product's OWN 25-harness registry on the
  host's PATH (single source of truth — no private list), and when a real
  agent CLI is available runs the full drill catalog with that CLI as the
  seat (verdicts are the model's, vouched, with one stable `overallDigest`).
  On a CLI-less host (like this build environment) the report says
  exactly that — per-harness inventory, reason, empty scenario list. It
  never fakes.

## 3. Benchmark integrity: the impossible scenario was leaking its answer

The validation work exposed a real hole in the drill's honest-failure
scenario: the `SEAL` token the test demands was a **hardcoded constant in
the generated test file** — a real model that could read the test would
simply encode it. The "impossible" scenario was impossible only for the
built-in seat's fixed playbook, not for a frontier model. Fixed and
pinned:

- **Per-run random 128-bit SEAL** (probe: two runs carry different SEALs).
- **The test file never enters a seat's worktree** — the seat that decides
  the outcome cannot read the judge. The canonical test is kept out of git
  (untracked in the base repo, in the forensic copy for the audit) and is
  **re-injected by the verifier before every verification run**, so seat
  tampering cannot survive to a verdict.
- **Test-file canary** (pure, exported, probe-pinned): classifies
  absent / ok / tampered; a tampered file is restored and labeled in the
  verification log.
- The deterministic verdicts are UNCHANGED (guard passed, maths passed,
  impossible failed — same attestations); the upgrade is integrity, not
  behavior.

This is the framework's benchmark-integrity section (leakage/shortcut
detection → quarantine) implemented at the point of proof.
