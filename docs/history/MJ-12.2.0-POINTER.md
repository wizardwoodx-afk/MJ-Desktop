# MJ 12.2.0 — provider precision on the Knowledge Forge

*Release pointer. Full notes live in the CHANGELOG row (12.2.0); this file
names what changed and where.*

## 1. The 12.1.1 review's one open item, closed

The 12.1.1 review (9.85/10) accepted the freeze except for one item: a
proposal that sent content to a provider recorded `dataHandling: "provider"`
but not WHICH provider — Anthropic, OpenAI, a local model, or an enterprise
proxy. 12.2.0 records vendor + endpoint class with an explicit basis, and
never pretends MJ knows an endpoint it cannot see. The reviewer's own words
set the honesty bar: record it "without pretending to know details the
harness doesn't expose."

## 2. What a provider-bound proposal now records

`KnowledgeProposal.providerInfo` (null when content never left the machine):

- `vendor` — the harness's default vendor when unconfigured (claude →
  Anthropic, codex → OpenAI, gemini → Google, grok → xAI, qwen → Alibaba
  Qwen, opencode → configurable). A labeled default, not a receipt.
- `endpointClass`: `cloud-default` | `local-configured` | `unknown`
- `endpointBasis`: `detected` | `user-declared` | `not-visible`
- `note` — the written reason, present on every record.

Resolution order (first that MJ can honestly know): a host-supplied
`readEnv` probe → **detected** (no override visible = cloud-default; loopback
override = local-configured; anything else = unknown with the reason — MJ
cannot tell where an enterprise proxy terminates); the user's declaration →
**user-declared**; otherwise the truthful default → **unknown** +
**not-visible**, reason written: MJ runs the harness with your environment
and cannot see its endpoint override settings. This matches the actual Tauri
surface (`cli_env` exposes PATH/searched/bins to the renderer, nothing more).

## 3. UI

The forge card's LLM pass gains an **ENDPOINT (your declaration)** select —
unsure / default cloud provider / local model. Proposals that went to a
provider chip `provider: <vendor> · <class>`; unknown classes are visually
distinct and carry the reason on hover. Mechanical distillations show no
provider chip.

## 4. Probe growth

`probe/knowledgeSkills.test.ts` 44 → **56/56**: the vendor-default table,
loopback classification (localhost/127.0.0.1/::1), the detected truth table
through scripted `readEnv` (no override → cloud-default; loopback →
local-configured; non-loopback → unknown; invalid URL → unknown; throwing
readEnv → not-visible), both user-declared branches, the not-visible default
with its reason pinned, and mechanical/local paths keeping `providerInfo:
null`. navAlign 42/42, missionLoop 80/80 unchanged (forge stays engine API).
