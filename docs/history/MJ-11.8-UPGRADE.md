# MJ 11.8.0 — THE TURN-LIMIT TRUTH

> The 11.7.1 review: *"I would promote 11.7.1 over 11.7.0, after fixing the remaining
> Claude `--max-turns` inconsistency and then running the full 40/40 gate once."* The
> finding was real — and the fix went the opposite way from the one proposed. This
> release closes the last known split between MJ's two argv layers, pins the whole class
> shut with a structural probe, and is the version the reviewer said 11.7.1 would become.

## 0. What the review found, and what was actually true

The reviewer correctly identified a legacy split that survived 11.4.1 → 11.7.1:

- `agentCapabilities.ts` said claude's `maxTurns` was **VERIFIED ABSENT** against the
  real binary (a `claude 2.1.197 --help` scan that found zero matches), with the gotcha
  "there is no turn-cap flag."
- `harnessPolicy.ts`'s `withTurnLimit()` **still emitted `--max-turns`** for claude —
  a hardcoded special case.

Two layers, two answers — the exact drift class the 11.6.2 "one harness truth"
consolidation was supposed to have ended. Credit to the review: it found it by reading
all three trees.

The review's proposed remedy was to **remove the flag from the policy and let MJ's
ledger be the only ceiling.** The 2026-09 web evidence says the opposite:

- The vendor's CLI reference documents `--max-turns` as a **print-mode-only** flag: no
  default, caps agentic turns, **exits with an error when the limit is reached**.
- Five independent 2026 sources (Feb–Aug 2026) cite and demonstrate it
  (`claude -p "…" --max-turns 5`), including its use inside the official GitHub Action.
- The old `2.1.197 --help` scan is real but stale/incomplete: the flag is documented
  while not appearing in `--help` (print-mode flags are documented separately).

So the correct fix was to **correct the registry**, not to strip the policy. (This is
the second time in this sequence a review found a real defect and inverted its remedy —
the instinct is trustworthy, the direction must still be verified. That habit is now
written into the probe comment.)

## 1. The fix, in three moves

**1. The registry tells the truth with its evidence attached.** claude's `maxTurns` is
restored at **docs** grade — not `binary`, because no live binary re-check happened in
this release; the source line records BOTH data points (the current vendor reference,
and the superseded `--help` scan). The file-header lesson paragraph gains a postscript:
the `--max-turns` saga now has three acts (docs said yes → a binary scan said no →
current docs say yes, with `--help` still silent). The lesson is unchanged: state the
evidence.

**2. `withTurnLimit()` is capability-driven.** The hardcoded
`id === "claude" ? ["--max-turns", limit]` special case is gone. The function now
composes whatever `AGENT_CAPABILITIES[id].maxTurns.argv` says, for any harness, filling
`$N` and inserting before `$PROMPT`. Claude's emitted argv is byte-identical to before.

**3. The second latent gap closed itself.** Grok has documented `--max-turns $N`
(docs.x.ai) in the registry since 11.6 — but the old special-case-only function ignored
it, so the `policyFor()` path never emitted grok's turn cap while the team-executor
path (`composeSeatArgv`, which IS capability-driven) did. The same split, one layer
over, invisible until the special case was removed. Grok write seats now get their
documented cap on both paths.

**On `--max-budget-usd`:** the vendor also documents a print-mode spend cap. MJ
deliberately does **not** compose it — the CapLedger is the spend authority (it kills
the run at `maxCostUsd`), and a second silent ceiling invites the two-layers-two-answers
bug this release just removed. The decision is recorded in claude's gotchas and pinned
by the probe.

## 2. The structural pin (probe suite #39 §10)

A point fix can regress; a structural check makes the class impossible:

- **For every spawnable harness**: `policyFor(id, write-request with maxTurns)` emits a
  turn flag **IFF** the registry documents one — 23 individual iff-assertions.
- claude's cap is docs-graded with the honest history (the source must still name the
  2.1.197 scan it supersedes).
- The registry no longer claims "VERIFIED ABSENT" for a flag the vendor documents.
- claude's write shape carries `--max-turns 5` **before** `$PROMPT`.
- grok's documented cap flows through the policy path (the second gap, closed).
- codex (no documented turn flag) still gets none — the ledger is its only ceiling.
- The hardcoded special case is gone from the source (pinned by text, like the Rust
  argv table).
- The `--max-budget-usd` decision is recorded where the probe can find it.

Suite #39 grows from 240 to **270 real assertions** (30 new). The registry count, derived
count (31), and all prior sections are unchanged — this release does not touch the
registry itself.

## 6. V11.8.1 — the environment-hardening patch

The 7th review (9.2 overall: runtime 9.5, harnesses 9.8 — best architecture yet;
verification robustness 8.6) did something no prior review had: it ran the shipped
offline gate **in its own environment**. 37 passed, 2 failed — and both failures were
real defects, not in what the code measured but in how it classified the environment
it measured in. Both are fixed here, and both are pinned by deterministic regressions
that fail on any machine, not just the reviewer's.

### 6.1 A wrapper that cannot be spawned is not enforcement (`sandbox.ts`)

On the review's machine, bubblewrap existed but could not be executed (`EACCES` — e.g.
a noexec mount or a confined profile). `verifyEnforcement` recognized only `ENOENT` as
"wrapper unavailable", so the spawn error was classified `absent: false, failed: true`
— and a must-fail canary that "failed as expected" **certified enforcement that never
ran**: a guaranteed false `enforced: true`, strictly worse than the missing-wrapper
case the code already handled honestly.

**Fix**: `WRAPPER_UNAVAILABLE = { ENOENT, EACCES, EPERM, ENOEXEC }` — every spawn
errno that means "the wrapper never started" now yields `measured: false,
enforced: false`, evidence that names the wrapper (`... is not installed or not
executable (EACCES) — the canary never ran`), and a note stating UNMEASURED plainly.
`execFile`'s non-zero-exit errors carry a *numeric* code, which can never collide with
the string set — a wrapper that genuinely ran and failed remains a measured run. The
timeout path ("timeout (treated as blocked)") is unchanged.

**Probe**: the sandbox probe grows 20 → 26 assertions. New §2.5 reproduces the
reviewer's machine deterministically — a temp file that is present, readable, and
deliberately not executable (chmod 0o644 → a real `EACCES` from the OS), fed through a
real `verifyEnforcement` call — and pins `measured: false`, `enforced: false`, no
`failedAsExpected`, the wrapper-naming detail, and the UNMEASURED note, plus the kept
ENOENT rule. §2's wrapper detection also no longer trusts `existsSync` (existence is
not usability): it now tries to run the wrapper and branches on what the canaries will
actually observe.

### 6.2 The exit code is the verdict; text is corroboration, never a veto (`evaluation.ts`)

The review's environment injected an unrelated artifact-tool startup `Traceback` into
captured stderr. `testRunCheck` matched `fail|error|✗|FAILED|panic:|Traceback`
*anywhere* in the output as a veto: a green pytest run — exit 0, "1 passed" — was
reported FAILED.

**Fix**: exit-code-first with runner-summary corroboration. A non-zero exit fails
regardless of cheerful text. A zero exit is overturned only by the runner's OWN
failure summary: a counted "N failed/failing/failures" with N > 0, a TAP `not ok`
line, a `FAILED` summary line, or a Go `panic:`. Ambient noise words can no longer
veto a measured pass; "0 failed" is a count, not a verdict; and — a bonus the review
did not ask for — the new logic catches TAP `not ok` failures the old regex silently
missed. The no-output → unmeasured rule is unchanged.

**Probe**: the checkRunner probe grows 36 → 45 assertions — the FIRST direct unit
tests of `testRunCheck` (through 11.8.0 it was only exercised end-to-end through real
pytest, which is exactly how an environment-dependent false-fail survived 39 suites).
Nine cases pin: the reviewer's exact case (pass), "3 passed, 1 failed" at exit 0
(fail), mocha's "1 failing" (fail), "0 failed" (pass), exit 1 + cheerful text (fail),
TAP `not ok` (fail), `panic:` (fail), bare noise words with no summary (pass), and
empty output (unmeasured).
