# MJ 14.0.0 — the Assurance release

**Theme: evidence as product.** 13.x built the governance engine; 14.0 turns its
evidence into customer-facing artifacts a finance team, a risk committee, or an
external auditor can consume without installing MJ.

## What is new

1. **Verify-anywhere CLI** — `tools/verify-receipt.mjs`
   A standalone, zero-dependency verifier (node: builtins only) for proof receipts:
   recomputes the SHA-256 chain, the HMAC seal, and the Ed25519 issuer signature.
   `node tools/verify-receipt.mjs receipt.jsonl` (or `-` for stdin). Exit 0 = VALID.
   Auditors run it on machines that never had MJ.
2. **Agent FinOps** — `src/mission/finOps.ts`
   Measured, receipt-backed chargeback rows per team/mission from the budget ledger's
   real settlements, with `verifyChargebackDigest` tamper evidence and RFC-4180 CSV
   export. Honesty rules kept: tokens-only seats are `unmeasured` (never priced),
   uncapped missions say `uncapped`, simulated seats are counted but never charged.
3. **Fleet Assurance Score** — `src/mission/assuranceScore.ts`
   A 0–100 score with a named factor breakdown (verification mix 35, governance arena
   20, budget discipline 20, egress integrity 15, human feedback 10), derived only from
   artifacts MJ already issues. Refuses to evaluate without measured runs; simulated
   runs dilute through evidence coverage and never add points.
4. **Incident black box** — `src/mission/incidentDossier.ts`
   One-file, digest-stamped forensic dossier per mission: canonical timeline,
   authority envelope id, and every proof receipt RE-VERIFIED live at build and at
   verify time. Broken evidence is marked, never laundered; a SIEM-shaped JSONL
   projection ships alongside.

4b. **Product surfaces (the integration pass)** — `src/mission/evidenceSurfaces.ts`
   reads the real mission-loop ledger, receipt vault and feedback store; the **Audit
   page** ships the Assurance Score card, the FinOps chargeback card with an
   egress-gated digest-stamped CSV export, and the black-box sealer with a mission
   picker. `probe/evidenceSurfaces.test.ts` pins the store-reading contract.

## Fixes folded into 14.0

- CI: the probe watchdog default is 300s (was 120s) with `MJ_PROBE_TIMEOUT_MS`
  override; CI sets it explicitly, configures runner git identity before the probes,
  and always uploads `probe-run.log` as an artifact — a red run is debuggable forever.
- Security: the receipt-issuer Ed25519 private key now seals into the **OS keychain**
  on the native desktop (new typed `secret_get` IPC command). The browser edition keeps
  the localStorage path; existing keys remain readable there, so no migration is needed.
- Portability: the browser-service directory and Node-runtime search no longer contain
  developer-machine paths (`%LOCALAPPDATA%\MJ\mj-browser`, standard Program Files).
- README: duplicated `## Verification` header repaired.

## Upgrade notes

- No state migration: 14.0 adds modules; stores, receipts and workflows are untouched.
  v1 and v2 receipts remain verifiable forever (the verifier accepts both).
- The verifier is intentionally dependency-free — do not add imports to it; the probe
  suite asserts its import list.
- CI runners now need nothing new (the git-identity and timeout steps are self-contained).
