# Vouch Harbor 16.0 — the merge (MJ executes · ROGUE governs · Vouch proves)

**16.0.0** is the first merged release of the Vouch Harbor plan (Step 3): the
complete MJ agent engine and the complete ROGUE control plane, fused into one
product with **one state, one event stream, one receipt chain**.

> Step 2 (MJ error fixes) was deferred by owner decision — the merge was built
> on MJ 15.1.0 as-is, all gates green.

## What is now true

**The Vouch door (the face).** The shell's face door is no longer MJ's 15.x
internal "Teammate" prototype — it is the ROGUE control plane: the accountable
colleague running the full Vouch Cycle (route → recall → plan → council →
signed simulation → human gate → act → vouch → learn), with threads, personas,
web evidence, memory OS and test-gated skills. MJ's `pages/TeammatePage.tsx`
is retired from the nav (still probe-covered, no longer a door).

**Dispatch is real (spec M1).** `dispatch a mission: …` in the Vouch door now
drives MJ's **real** mission loop — composed seats, harnesses, the inter-agent
bus, the gate, retry — through a single isolated seam (`src/rogue/engine/bridge.ts`;
the only file in the ROGUE tree that reaches the MJ engine, probe-pinned by a
static scan). Nothing is re-implemented or faked: on a host without a reachable
CLI agent, seats report *blocked* — MJ's own honesty — and the receipt says so.

**One mission ID, one chain (spec §2).** Each dispatch mints a `mission_xxxx`
that rides the job end-to-end. The loop's execution events are projected as
`mission.*` events into the **same** `mj-proof-receipt/2` chain that carries the
ROGUE control events (`rogue.session/.deliberation/.simulation/.dispatch/.verdict`).
The dispatch event carries the mission payload (status, seats verified, gate,
engine provenance). Flip 1 byte anywhere in the chain → verification fails
(probe-pinned, including on merged chains).

**One state.** The product-level mission ledger (`rogue.missions.v1`) is the
only mission store in the control plane (probe-pinned). The engine's internal
state stays in MJ's modules; there is no second mission store. The receipt
header now stamps the product version (16.0.0) — one product, one version line;
ROGUE's 1.x line survives as provenance inside the events (`controlPlane`).

**The mission ledger UI.** The Vouch door's memory rail gained a MISSIONS tab:
every dispatched mission with its honest status, seats verified, gate, receipt
and engine provenance.

## What was NOT done (honestly)

- **M3 — MCP capability router** (external servers through the Vouch-wrapped
  call path): not yet. MCP calls are not part of this release.
- **M4 — learning bridge** (MJ trajectories → distillation fuel for test-gated
  skills): not yet. ROGUE's slow→fast distillation runs on ROGUE's own runs.
- **M6 — META-LOOP** (gated self-release): not yet; it is locked last, per the
  spec.
- **Native re-verification:** `src-tauri` was rebranded (product "Vouch Harbor",
  16.0.0, crate `vouchharbor`) — the Rust source is unchanged except manifest
  values, and the shell's `cargo check`/`cargo test` were green on the
  pre-rebrand source. Re-run `cargo check` on a machine with the toolchain
  before building the installer (`INSTALL-ON-LAPTOP.md`).
