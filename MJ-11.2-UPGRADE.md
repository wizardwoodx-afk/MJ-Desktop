# MJ 11.2 — UPGRADE

The change in one sentence: **11.2 is the release that fixes the canvas the way a
canvas is supposed to behave (mouse wheel zooms toward the cursor — it never moves
the nodes; wires connect at measured port anchors, not guessed coordinates), turns
the Teams page into a living system with a **self-evolve loop** and a **feedback
loop**, and replaces the twelve-theme pile with one design system — the INSCRIBED
family, upgraded from the Nothing OS theme, five new palettes, zero old themes.**

## 1. What V11.2 fixes over 11.1

### 1a. The scroll bug — wheel zoom, not node pan (the one the user kept hitting)

`src/canvas/Canvas.tsx` previously handled a **plain wheel event by panning the
viewport** (`setViewport({ x: vp.x - e.deltaX, y: vp.y - e.deltaY })`) — the nodes
moved up and down with the scroll, and zoom was only reachable through Ctrl/Cmd+wheel
(which many trackpads never deliver). V11.2:

- **Plain wheel now zooms, cursor-anchored.** `wheel` is attached to the canvas as a
  native, non-passive listener (`addEventListener("wheel", onWheelNative, { passive: false })`)
  so `preventDefault()` actually fires and the page never fights the canvas.
- The zoom math is `zoomAt(viewport, cursor, e.deltaY, e.deltaMode)` from
  `src/canvas/geometry.ts` — the world point **under the cursor stays under the
  cursor** through every zoom step (the property the geometry probe proves over 12
  chained steps), with `deltaMode` normalisation (Firefox "lines" vs Chrome "pixels")
  and clamp at 0.2×–2.4×.
- **Shift+wheel = horizontal pan** (trackpads put their horizontal scroll in `deltaX` here);
  **Ctrl/Cmd+wheel also zooms** (browser-style pinch / page-zoom gestures). Everything
  horizontal or modifier-bearing keeps its old meaning — only a *plain* wheel now means
  zoom, which is what the user asked for.

### 1b. Wires connect where the ports actually are — measured anchors

Wires used to be drawn from `portPos()` — a formula (`nodeH()` + row index × row
height). The moment a card's header or a wrapped purpose-preview changed height, the
formula was wrong and the wire ended up floating above or below the port. V11.2 goes
through `src/canvas/ports.ts`:

- Every port anchor registers itself with the DOM's own geometry
  (`registerPortAnchor(id, getRect)`, walked through the real `offsetParent` chain:
  `.port-anchor → .port-row → .port-col → .port-grid → .node-card`).
- `measureCardHeight(nodeId, cardEl)` measures the card it *actually rendered* —
  header, purpose preview, stream preview included — and `invalidatePortMetrics()`
  bumps a `useSyncExternalStore` version so the wire layer re-renders when anything
  reflows. A `ResizeObserver` on each card re-measures on every layout change.
- Wires are drawn as `geomPortPos(nodeId, portId, dir, metrics)` → the curve starts
  and ends **exactly on the anchor**, with the minimum-bow rule for short/right-to-left
  wires preserved.
- The ghost wire (drag from an output) snaps to the measured rect of a hovered valid
  input, and invalid outputs are rejected by the same `wireTargets` check as before.
- The geometry probe grew a **source-level section** asserting the Canvas component
  imports `zoomAt`, has no old pan-on-plain-wheel branch, registers anchors, calls
  `geomPortPos`, invalidates port metrics on DOM change, and observes card reflow —
  so the fixes cannot silently drift out again.

### 1c. Teams — the self-evolve loop and the feedback loop

`src/mission/teamEvolution.ts` (one module, covered by its own probe section):

- **Self-evolve loop, three modes** (`TeamEvolveMode`): `OFF` (nothing happens),
  `SUGGEST` (a candidate team change is proposed, human applies), `AUTONOMOUS`
  (the evolved team is applied automatically, `decidedBy: "team-evolver"`).
- **The gate** requires a real track record, not vibes: `minRuns 3`, `minRealRuns 2`
  (simulated harness runs don't count toward the hard gate), **cumulative evidence
  weight ≥ 3** — failed runs weigh 2, unverified runs and negative feedback weigh 1,
  cost spikes weigh 2. Evidence **accumulates across runs** on the seat (`evidence`
  array, newest-first, cap 8) instead of being recomputed from the current signal —
  this was the design bug that made a 3-run ledger unable to ever trigger.
- **Growth budget**: max +20% of a building block's baseline size, minimum meaningful
  change 300 chars; instructions capped at 8000 chars, evidence bullets capped at 5.
- **Feedback loop**: `applyTeamFeedback({ teamId, seatId, runId, rating, comment })`
  queues rating + comment on the seat (`pendingFeedback`), records it in
  `store.feedback`, and folds it into the next evolution as evidence weight 2.
  **Praise is load-bearing, not decorative**: 3 consecutive high ratings suppress
  candidate creation for the next 3 runs, and the probe proves it (2 failures → 3
  praised runs → no candidate; the 7th failure then produces one).
- Consent is explicit: feedback applies to the seat a run *actually* executed
  (`lastRunSeat`), candidates are never applied while the run they'd change is still
  in flight, and every decision is written back to `store.decisions` so the org
  ledger stays the honest record.

### 1d. The INSCRIBED theme system — one design system, six palettes, old set removed

The V10.1 `nothing` theme (Nothing OS: OLED black, `#1B1B1D` surfaces, signal red
`#D71921`, dot-matrix display type) is **upgraded into the INSCRIBED family**, and
the old twelve-theme set is **removed** — `src/graph/store.ts` `THEME_IDS` now
accepts exactly `["inscribed", "chalk", "carbon", "bone", "indigo", "sage"]`, and
the prefs migration maps a stored old theme name to the new default instead of
silently dropping it:

| Theme | Light/Dark | Canvas | Ink/data | Accent |
|---|---|---|---|---|
| `inscribed` | dark | true OLED black | white | signal red `#D71921` |
| `chalk` | light | chalk white | black ink | signal red |
| `carbon` | dark | industrial cool grey | white | phosphor green |
| `bone` | light | warm parchment | sepia | terracotta |
| `indigo` | dark | deep slate indigo | ice white | ice blue |
| `sage` | light | soft botanical | forest ink | forest green |

Architecture (`src/styles/themes.css`): all component rules are **shared through
`:is()`** so a palette is *only* a token block — adding a theme means writing tokens,
never copying rules. The design rules are pinned in the file header: monochrome
canvas + one accent per theme; Space Grotesk for content, Space Mono for ALL-CAPS
labels/numbers, Doto for the single hero moment; no shadows, no gradients, no
backdrop blur, hairline borders instead of elevation; percussive `90–140ms`
cubic-bezier motion instead of springs. The dot-matrix Doto font is bundled as
non-trivial woff2 and declared in `fonts.css` (the theme probe checks it).

## 2. The version-drift close — why this ledger exists

The tree's own probes (`probe/versionDrift.test.ts`, `probe/theme.test.ts`) failed
the moment `11.2.0` landed: `LOCAL-WORKLIST.md` still titled "MJ 11.1" and this
ledger did not exist. Both are fixed in the source, not the probe — every manifest
says 11.2.0, the shipped doc titles name the current release, and this file is the
release note for 11.2.
