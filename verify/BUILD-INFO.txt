MJ 14.1.3 — offline verification pack provenance
===================================================

Release identity: MJ 14.1.3 — "the honesty patch."
Four defects where the tree claimed more than the build did, each fixed and
pinned by a probe:

  1. FALSE FAILURE FROM A WRONG CAPABILITY PROBE: probe/realExecution.test.ts
     read `have("python3")` into a constant named HAS_PYTEST. On any host with
     python3 but no pytest the suite entered the branch its own header promises
     to skip, ran the real checks, and failed 3 assertions ("a passing suite
     must exit 0, got 1"). Because the suite ships inside this pack, that one
     missing binary took `node verify/run.mjs` to 79 passed / 1 failed with
     exit 1 on a machine the docs described as needing nothing but Node. The
     probe now asks the question checkRunner actually asks — `python3 -m
     pytest` (src/mission/checkRunner.ts:106), never the `pytest` console
     script — and the skip names the missing half of the toolchain.
  2. CAPABILITIES THAT REPORTED SUCCESS WITHOUT RUNNING: cap.cron and
     cap.webhook fell through runCapability's pass-through return and emitted
     NODE_SUCCEEDED having scheduled nothing and delivered nothing — the same
     silent fake cap.http already refused. Both now refuse in that voice,
     NODE_METHODS gains a second honest marker "(declared, not built)", and
     probe/meridian fails the build if any capability the runner refuses still
     claims "(built in)". cap.vector keeps its built-in marker; its method
     text now matches what memory_search really does (substring recall ordered
     by importance — not embeddings, not k-nearest-neighbours).
  3. DOC OVER-PROMISE: docs/VERIFICATION.md called Tier 1 "zero install (any
     machine with Node.js)". Node.js and git are required; python3 -m pytest
     and cargo are optional and now skip cleanly.
  4. A DEPENDENCY THAT IMPLIED A CAPABILITY: playwright and puppeteer-core had
     zero call sites in this tree and are removed from package.json. The
     external mj-browser service the Browser screen forwards to is documented
     in docs/PLATFORM-LIMITS.md instead.

Trust model carried from 14.1.1/14.1.2 (unchanged): --issuer-key pins the
trusted Ed25519 key out-of-band; no pin -> issuer UNVERIFIED (exit 3);
mismatch -> INVALID (exit 1); match -> issuer AUTHENTICATED (exit 0). Mission
economics spans every cycle (perCycle + totals). Claim language: zero MJ state
required, issuer key pinned out-of-band — never "zero trust".

14.1.3 — upgrade notes
----------------------
  1. No state migration; records sealed by earlier releases remain verifiable
     (their recorded mjVersion is historical fact, like any receipt).
  2. A workflow containing a Schedule or Webhook node now FAILS that node with
     a stated reason instead of silently succeeding. That is the intended
     behaviour change: nothing was ever scheduled or delivered before either.
  3. Both verifiers stay dependency-free (probes pin their import lists).
  4. Release ritual unchanged: tag v14.1.3; release.yml re-runs the gates.
