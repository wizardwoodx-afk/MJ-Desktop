MJ 12.0.1 — offline verification pack provenance
===================================================

Release identity: MJ 12.0.1 — "The Human-Feedback-in-the-Loop patch" (the
12.0.0 review's open items, closed). The review confirmed the ONE-ENGINE
fusion — missionLoop.ts orchestrates teams, self-evolution, feedback,
adaptive learning and communication as phases of one runtime — and flagged
three gaps, all closed in 12.0.1: (1) the explicit human feedback
interaction (1-5 rating + comment) is back INSIDE the Loop: engine API
submitHumanFeedback() queues the rating on every seat that ran the cycle
through the same applyTeamFeedback pipeline the pre-12.0 Teams page used,
and the next ADAPT fold turns it into real evidence (1-2 = weight-2
"Human: <comment>" evidence, 4-5 = praise suppression, 3 neutral); the Loop
page renders the rating panel on every ledger cycle. (2) The Loop page now
imports the engine module ONLY — crew persistence (loadCrews/persistCrew),
the host-deps adapter (loopHostDeps) and the bus projection (loopBusFeed)
moved behind missionLoop's API; navAlign's forbidden list includes
agentTeam/hostDeps/interAgentChannel. (3) The claims now state the precise
architecture: ONE canonical orchestrator over the engines of record (team
evolution, autonomy/bandit, lessons, receipts, bus, crew persistence) with
one cycle ledger (mj.missionLoop.v1) — NOT one physical store; the module
header, IA doc, changelog and README say exactly that, and navAlign pins
the wording.

12.0.1 — what changed over 12.0.0
---------------------------------
  1. THE EXPLICIT HUMAN FEEDBACK SURFACE IS BACK, INSIDE THE LOOP.
     submitHumanFeedback() is engine API; the Loop page renders a 1-5 +
     comment panel on every ledger cycle. Ratings queue on every seat that
     ran and fold into real evidence at the next ADAPT (1-2 criticism =
     weight-2 "Human: ..." evidence with the comment preserved; 4-5 =
     praise suppression, never invented criticism; 3 = neutral). Invalid
     ratings and unknown cycles are refused without touching any store.
     probe/missionLoop.test.ts grew 56 -> 67 assertions.
  2. THE PAGE TALKS TO THE ENGINE ONLY. Crew persistence, host deps and the
     bus projection moved behind missionLoop's API (loadCrews/persistCrew,
     loopHostDeps, loopBusFeed). navAlign grew 32 -> 39 assertions incl. the
     new forbidden modules (agentTeam, hostDeps, interAgentChannel).
  3. PRECISE CLAIMS. The module header and every product doc now say what the
     architecture is: one canonical orchestrator over the engines of record
     with one cycle ledger — not one physical store. navAlign pins the
     wording; the honest model cannot drift back into an overclaim.
