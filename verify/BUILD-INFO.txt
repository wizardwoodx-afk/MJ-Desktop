MJ 12.0.0 — offline verification pack provenance
===================================================

Release identity: MJ 12.0.0 — "ONE ENGINE — the Mission Loop" (the real
consolidation: 11.14.10 organized the shelves, 12.0 fuses the machinery).
Reviews of the 11.14 line were right twice: the app's features were still
separate productions inside one app — TEAMS, team self-evolution, the
feedback loop, adaptive learning and agent communication, each with its own
store, page and vocabulary. 12.0 merges them into ONE runtime:
src/mission/missionLoop.ts owns the whole cycle — COMPOSE -> DISPATCH ->
COMMUNICATE -> EXECUTE -> GATE -> ADAPT — and folds every measured outcome
through the SAME engines (seat signals -> human-gated team-evolution
candidates, bandit + elastic settlement, lesson reflection, one signed
proof receipt per cycle) into ONE loop ledger (mj.missionLoop.v1). The
product surface collapses to one engine screen + five doors: Mission Loop /
Workflows / Proof / Audit / System (PageKind trimmed to the five; legacy
feature pages stay in the tree only where probes exercise them, no longer
navigable). The lifecycle MJ narrated since 11.14.10 runs INSIDE the engine
as its real phase rail; the Loop page imports the engine only, never the
fragment stores (navAlign pins that).

12.0.0 — what changed over 11.14.11
-----------------------------------
  1. ONE RUNTIME. missionLoop.ts owns the whole cycle: COMPOSE (crew from
     the bandit-shaped seat plan) -> DISPATCH (seats + briefs) ->
     COMMUNICATE (every dispatch/event published on role channels) ->
     EXECUTE (real gated team missions on real git worktrees) -> GATE
     (arena + budget + verify verdicts ARE the feedback) -> ADAPT (seat
     signals fold through team evolution and bandit settlement; lessons
     reflect; one signed proof receipt per cycle). One loop ledger key:
     mj.missionLoop.v1.
  2. ONE SURFACE. PageKind trimmed to five doors (Mission Loop / Workflows /
     Proof / Audit / System); the Loop page composes the crew, runs cycles,
     shows the live bus, holds the human gate on adaptation proposals and
     lists the cycle ledger with receipts — and imports the engine module
     only. navAlign re-pinned 30 -> 32 (no orphan routes, engine-import
     rule, phase rail == engine arc).
  3. THE HEALING ARC IS PROBED. probe/missionLoop.test.ts (56/56): three
     measured failing cycles produce a seat candidate from evidence; a
     human REJECT is recorded and changes nothing (no pretend learning);
     a human ACCEPT applies a superset instruction edit; the next cycles
     complete verified; receipts verify end to end; OFF mode records
     telemetry but proposes nothing.
