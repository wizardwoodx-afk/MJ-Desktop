Vouch Harbor 16.8.0 — offline verification pack provenance
==========================================================

Release identity: Vouch Harbor 16.8.0 — "govern · execute · verify · learn."
The capability-genome release: VH-COLOR Phase 1 — the open standard's core
unit, the CAPABILITY GENOME, around the invariant the standard exists for
("evolution may change capability / may not control its own safety
authority" — already VH's M6 tighten-only loop, now the promotion gate G1):
versioned genomes climb OBSERVED → CANDIDATE → UNDER_EVALUATION → SHADOW →
CANARY → ACTIVE through four hard gates (safety / provenance /
dependencies / zero-regression) where a failure QUARANTINES with the stated
reason; trust grades C0–C5 derive from the provenance chain only; signed
capability packages (canonical digest + Ed25519 from the receipt
keychain) are portable yet re-earn trust on import; production regressions
auto-rollback with fallback to the last ACTIVE version; existing M4 skills
convert to genomes with receipts and seats intact.

What 16.8 adds over 16.7
  - CAPABILITY GENOME — src/vouch/engine/genome.ts + probe/genome (91st
    suite, 56 assertions): the §11 entity (objective, trigger, procedure,
    declared failure modes, resource limits, provenance, append-only
    evolution memory); the §31 state machine pinned table-exact (five
    negative states, all terminal except quarantine); promotion as a LINE

    active genome).

    SEPARATE argument to promote(); a grant written into the genome's own

    per host).
  - AUTO-ROLLBACK — monitor() rolls an ACTIVE genome back on a production
    regression without a human in the loop; the host serves the last
    ACTIVE lineage version (roll back, don't fail; "off", not "old").
  - NO NEW MCP SURFACE — the 20-tool conformance pin, the dual-era wire
    and the SDK-client suite hold untouched (capability_* tools are
    Phase 2). No new dependencies.
