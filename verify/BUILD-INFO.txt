11.10.7 — what the re-probe pins (the CI post-mortem, enforced)
  realExecution   "an interpreter exists" is not "pytest exists": with pytest
                  importable, the real green/red/refusal contract runs against
                  repositories on disk; with a bare python3, the suite asserts the
                  checkRunner's REFUSAL (didRun=false, no exit code, the missing
                  pytest package named in the reason); only a host with no Python
                  at all skips, saying so. The machine-absolute cargo path is gone
                  in favour of a portable $HOME/.cargo/bin lookup.
  checkRunner     runCheck refuses pytest when `python3 -m pytest --version`
                  fails — a missing runner is UNMEASURED, never a phantom failure.
                  This is the fix for the CI run #52 red on GitHub's ubuntu-24.04
                  and macos-15 images (which ship python3 without pytest while the
                  Windows image ships neither and masked the gap).
