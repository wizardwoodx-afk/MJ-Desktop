# MJ 11.7.1 — THE OFFLINE GATE + THE SEPTEMBER-2026 REGISTRY

> The 11.7.0 review ended: *"Yes — this is the version I would build forward from"* —
> because *"the system that tells you whether the features work has finally been made
> falsifiable."* It also honestly declined one thing: certifying the runtime test result.
> Its environment had no `node_modules` (the zip ships none), could not `npm ci` offline,
> and bare `tsc --noEmit` dies on missing React types before it produces a usable exit
> code. This release closes that one open caveat — and, because a verification release
> should still move the product, grows the registry with four more harnesses.

## 0. What shipped

Two things, deliberately in one release:

1. **The Offline Gate.** The zip now carries `verify/`: every runtime probe suite
   pre-bundled into a self-contained `.mjs` (no npm packages needed at runtime), a
   zero-dependency runner (`verify/run.mjs`), and a sha256 manifest. Anyone with Node
   reproduces the full gate from the extracted zip — zero install, zero network, ~25 s:

   ```
   node verify/run.mjs
   OFFLINE VERIFY SUMMARY: 39 passed, 0 failed.
   ```

2. **The registry grew from 21 to **25** ids.** Four new harnesses, each with a
   VENDOR-documented headless prompt mode — the first registry growth in MJ's history
   where no base argv is community-graded:

   | id | binary | headless invocation | source (checked 2026-09) |
   |---|---|---|---|
   | `droid` | `droid` | `droid exec "$PROMPT"` | docs.factory.ai/droid-exec |
   | `kimi` | `kimi` | `kimi -p "$PROMPT"` | kimi.ai cheat sheet + moonshotai/kimi-code |
   | `auggie` | `auggie` | `auggie --print "$PROMPT"` | docs.augmentcode.com/cli/reference |
   | `warp` | `oz` | `oz agent run --prompt "$PROMPT"` | docs.warp.dev/reference/cli |

   Research candidates that did NOT make the cut are listed in §6, with reasons.

## 1. The four additions, honestly graded

**Droid (Factory)** — `droid exec` is a single non-interactive pass. The interesting part
is its default: **spec-mode, read-only operations only**. Droid is the rare CLI whose
headless mode is read-only *by construction*, so MJ's READ_ONLY policy for droid is the
bare registry shape — no flag needed — and the WRITE policy must compose the vendor's
documented autonomy tier instead: `exec --auto low "$PROMPT"` ("add --auto to enable
edits and commands, with risk tiers gating what can run"). That is the one hand-tuned
policy shape this release adds, and the probe pins both directions: the read-only shape
must stay the bare default, the write shape must carry `--auto low`.

**Kimi Code (Moonshot)** — `kimi -p` runs a single prompt non-interactively (the CLI's
`finalizeHeadlessRun` exits after completion). The vendor flag table also documents
`--output-format stream-json` (JSONL, scripting-grade — modelled as the json capability,
kind `ndjson`), `--yolo` (auto-approve regular tool calls — modelled as fullAuto), and
`-S <id>` / `--session <id>` resume-by-id — which flows through the SAME session layer
as claude/opencode with zero session-code changes, because the resolver owns it:
`sessionArgv("kimi", { kind: "resume" })` → `["--session", "<id>"]`, continuity
`session`. Kimi is honest about who assigns ids (cli-chosen; no documented
create-under-id flag).

**Auggie (Augment Code)** — `auggie --print` runs one instruction and exits ("perfect
for automation workflows", per the vendor). `--output-format json` structures the
response. One nuance modelled conservatively: `--ask` is a genuine read-only mode
("retrieval and non-editing tools only") but is documented as a mode of its own — the
combination `--print --ask` is not shown in vendor docs, so the capability registry
does NOT claim it (readOnly stays `null`, the gotcha and notes record `--ask`). The
enterprise licensing gotcha is recorded too: non-interactive mode may be disabled by
agreement.

**Warp (Oz Agent CLI)** — Warp's agent infrastructure has its own CLI, `oz`
(docs.warp.dev/reference/cli). `oz agent run --prompt` starts a LOCAL agent run — that
is what MJ spawns. `oz agent run-cloud` needs `--environment` and is Warp cloud
infrastructure; the registry notes say explicitly that it is NOT composed. `WARP_API_KEY`
authenticates headless servers (CI-grade). Like antigravity→`agy`, the id is not the
bin: `warp` → `oz`, and the Rust detect/allowlist/env tables all agree (pinned by
probe; `warp-terminal` — the Linux desktop launcher — must never appear as a harness
bin).

## 3. The Offline Gate

**Why.** The 11.7.0 review could not run `npm ci` in its environment, and `npm test`
needs node_modules at runtime: the dev runner bundles each probe with
`packages: "external"`, so React and friends resolve from `node_modules` when the suite
executes. A shipped gate that only runs with a package registry available is a gate
that an offline reviewer must take on faith.

**What.** `tools/build-offline-verify.mjs` bundles every probe suite (except its own
verifier, suite #40) with packages bundled IN, `MJ_ROOT` defined as `"."` (so the pack
works from any extraction path — the dev runner instead bakes the absolute checkout
path at build time), and a `createRequire` banner for the one CommonJS wrinkle
(`react-dom/server` require()s node builtins; without the banner the v10Page suite dies
on "Dynamic require of 'stream' is not supported"). Output: `verify/suites/*.mjs` +
`verify/MANIFEST.json` (sha256 per bundle, MJ version, exact esbuild version).
`verify/run.mjs` executes each bundle with cwd = the tree root using ONLY `node:`
builtins.

**Freshness, not faith.** The pack is generated, but it is not trusted blindly:

- `tools/probe-list.mjs` is the single suite list both runners consume — the pack and
  `npm test` cannot cover different sets.
- **Suite #40** (`probe/offlinePack.test.ts`) is the pack's freshness gate, run by
  `npm test`: it rebuilds every bundle and asserts byte-identity with the committed
  `verify/suites/`, validates every MANIFEST hash against the files on disk, checks
  the manifest names this release and the exact esbuild that built it, then EXECUTES
  `node verify/run.mjs` and asserts N/N + exit 0.
- Suite #40 is deliberately not packed: it is the gate FOR the pack, meaningful only
  where the dev toolchain exists. Inside the offline pack it would only re-run the
  other suites.

**Reviewer credit.** This exists because the 11.7.0 review stated its limits precisely
instead of quietly skipping them — the same honesty standard MJ holds itself to.

### 5.1 Mutation tests (the 11.7.0 lesson, applied to the new assertions)

1. Registry count: flip `HARNESSES.length === 25` → `26` in suite #39 — the suite fails
   loudly (the count check named, 239/1); revert — green again.
2. Offline-pack freshness: append one byte to a committed `verify/suites/*.mjs` — suite
   #40 fails with the drifted bundle named (byte-identity AND manifest hash, 13/2);
   restore — green again (15/0).

**Mutation #2 earned its keep.** The first version of suite #40 reported 14/0 against a
tampered pack. Root cause: `tools/build-offline-verify.mjs` decided "am I the CLI?"
with `process.argv[1] === fileURLToPath(import.meta.url)` — which is ALSO true inside
suite #40's esbuild bundle (there, `import.meta.url` IS the bundle). Every #40 run was
silently rebuilding the pack in place before comparing — a freshness check comparing a
fresh build against itself. The vacuous-gate class of defect, in the very suite built to
prevent it, caught by the discipline 11.7.0 installed. Fixed twice over: the module now
fires CLI mode only when run under its own filename, and suite #40 snapshots the pack's
hashes before verification and asserts they are byte-unchanged after it — the pack is
INPUT to the verification, never output, so any in-run mutation is a loud failure
regardless of cause.

### 5.2 Research candidates NOT added (and why)

- **Warp's older `warp agent run` surface** — superseded by the Oz CLI for agent runs;
  the `warp` binary is the desktop launcher (not composed as a harness bin).
- **Roo Code / Continue / Cody-style IDE extensions** — not standalone spawnable CLIs
  with a documented headless prompt mode.
- **aichat / Shell-GPT** — scripting assistants, not agentic file-editing harnesses.
- **Long-tail CLIs seen in 2026 roundups without vendor-documented headless modes** —
  MJ's registry only adds what it can grade honestly; community-graded base argvs are
  legacy (the 2026-09 rule: new ids need vendor docs, like these four).
